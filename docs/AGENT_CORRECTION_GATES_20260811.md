# Agent 纠偏与硬门禁指令

> 2026-08-11 范围更新：本文中的 960x540 强制门禁已由
> `docs/SCOPE_OVERRIDE_1600X900_20260811.md` 覆盖。首发只验收游戏真实支持的
> 1600x900；960x540 记为 NOT_APPLICABLE，不再要求用户采集。

用途：发给当前正在执行改造的 Agent，立即纠正越级推进、waiver 混淆和“测试通过即实机可用”的表述。

## 可直接复制发送

```text
【立即纠偏：冻结越级推进，恢复硬门禁语义】

你目前的工作量和代码产出是有效的，但执行顺序已出现越过硬门禁的风险。收到本指令后，立即停止新增生产行为，不要继续开启 G0 龙珠/秘境/黑商，不要把 P0 策略接入 LIVE，不要把 O4 shadow 接入 mediator，不要修改 mediator.py 以“补齐进度”。先完成状态收敛和证据校验。

一、硬状态必须按以下规则重写

1. O3 当前状态必须是 CONDITIONAL_FAIL/BLOCKED，不得写 PASS：
   - held-out Top-1 98.19%：PASS；
   - skill recall 96.92%：FAIL，不能用 waiver 改写为 PASS；
   - progress 95.24%：PASS；
   - negative-panel suggestions 0：PASS；
   - 960x540 真实正样本 0：BLOCKED；
   - RSS 456–684MB：记录实测值，不能只写“满足蓝图 ≤800MB”而隐藏区间；
   - 断线恢复真实素材缺失：BLOCKED。

2. waiver 只能表示“暂缓该项，不改变门禁结论”，格式必须是：
   status=FAIL 或 BLOCKED；waiver=true；owner；补证据条件；截止阶段。
   禁止出现“FAIL + waiver = PASS”。

3. 只有所有硬门禁满足后，才能进入下一阶段。当前禁止宣称：
   - OCR 已可用于生产动作；
   - 断线恢复已通过实机验证；
   - 支持 960x540；
   - 支持长期无人值守；
   - 龙珠/秘境/黑商已完成。

二、当前允许做的事情

1. 完成并提交 O4 shadow 的协议、崩溃、超时、缓存失效测试；保持 shadow-only。
2. 用真实模型目录重新跑 O4：至少 10,000 个请求、实际推理而不是 model_missing/unavailable 路径；分别报告单槽 P50/P95、三槽 panel P95、RSS 起止/增量、子进程数、错误数、模型加载时间。
3. 对 O3 报告做状态纠正，删除“waiver 后 PASS”的措辞；不删除历史报告，新增修正版报告并注明依据提交 SHA。
4. 运行完整测试和 off/shadow action ledger diff；确认 O4、P0 没有任何输入动作权。
5. 整理当前未提交文件，禁止删除、覆盖或静默丢弃；先列出 status、diff --stat、测试结果，再决定是否提交 checkpoint。

三、当前禁止做的事情

1. 禁止修改 mediator.py、scenes.json、settings.py、输入执行器，把 O4/P0 接入生产。
2. 禁止把技能非预设 fallback 改成可点击。技能只能选配置技能；OCR unknown 必须刷新/放弃/关闭。
3. 禁止把 1600x900 缩放图计为真实 960x540 样本。
4. 禁止用缺失模型压力测试替代真实 OCR 压力测试，并写成“模型稳定”。两者必须分开命名和判定。
5. 禁止把单元测试、replay ledger 或模拟 fixture 当作实机恢复证据。
6. 禁止为赶进度增加新的 XFAIL、降低阈值、修改分母、删除失败样本或把未知 truth 强行归一化。
7. 禁止继续扩展 G0 后段链路，直到 O3、O4、S0 的阻塞项都有明确证据。

四、下一阶段唯一合法入口

在没有用户提供真实 960x540 正面板和真实断线弹窗前，下一工作只能是：
   A. O4 shadow 的真实模型压测与协议验收；或
   B. R0 录制/采集工具和报告模板；或
   C. 纯离线评测修复。
三者都不得产生游戏输入。

五、交付报告必须逐项回答

1. 当前 HEAD 和工作树状态；
2. 哪些文件被修改，哪些仍未提交；
3. O3 每个门禁的 PASS/FAIL/BLOCKED 原始数字；
4. O4 是否实际加载真实模型，模型 SHA/size 是否校验；
5. O4 10k 实际推理的单槽/三槽 P50/P95、RSS、错误、子进程数；
6. `ocr_mode=off` 与 `ocr_mode=shadow` 的 action ledger diff；
7. 全量测试命令、通过数、失败数、XFAIL 数；
8. 当前仍缺少的实机证据；
9. 下一步是否需要用户操作；
10. 明确结论只能是 PASS、FAIL 或 BLOCKED，不得使用“基本通过”“waiver 后通过”“理论可用”等模糊措辞。

六、停止条件

只要出现以下任一情况，立即停止继续扩展功能并报告：

- 真实模型压测未完成；
- 960x540 或断线实机证据缺失；
- ledger diff 非零；
- 测试失败或新增 XFAIL；
- 任何任务试图修改生产输入路径；
- 报告中的门禁状态与原始数字不一致。

本指令不是要求回退已有工作，而是要求保留已有提交、纠正状态、停止越级，并把下一步限定在可验证的离线/采集工作。
```

## 发送后人工检查

Agent 回报后只检查以下四项：

1. `git status` 是否明确列出 O4 未提交文件，没有静默删除；
2. O3 报告是否明确为 CONDITIONAL_FAIL/BLOCKED；
3. O4 是否真的使用模型目录，而不是 `model_missing` 压测；
4. 是否仍未修改生产输入接线路径。

四项未同时满足前，不批准下一轮生产改造。
