# GameScript-Local 最小自动化路线（2026-08-08）

## 当前可交付基线

面板和运行入口只保留：精确关卡、普通/英雄模式、英雄阵营与难度、技能、安全测试、开始/停止、局数和折叠日志。

普通模式的离线时序回放现已覆盖：

```text
胜利继续
→ 关闭存档面板
→ 挑战广场
→ 左上专用退出
→ 专用“确认退出”
→ 验证回到原 KK 房间
→ 房间开始
→ 精确选关
→ 开始游戏
→ 第二局 MAIN_LINE
```

`game_count` 只在重新识别到原房间后增加；回房超时会停止，不会猜测重建房间。未知选择面板最多尝试三次“暂时隐藏”，之后明确报错，不再永久等待。

## P0：普通模式真机门禁

1. 先以“安全测试”运行，确认日志依次识别房间、选关、主线和结算页面。
2. 再做一次有人值守的真机两局测试，保留 `%LOCALAPPDATA%\GameScript-Local\logs\GameScript.log`。
3. 验收条件：同一房间号、只创建一次房间、`game_count == 1` 后进入第二局主线、每帧最多一个输入、Shift+F12 可停止。
4. 若确认退出后未返回原房间，只补该一步的后置证据；不得启用“重新建房”兜底。

## P1：英雄模式

当前真机启动被安全阻断，因为后端依赖的 `cancelChallenge/quxiao/startChallenge/kaishiChallenge` 四个模板均不存在。放开前需要同一次操作的连续全屏帧：

1. 点击英雄模式前；
2. 弹窗出现；
3. 选阵营后；
4. 设置难度后；
5. 点击开启挑战后进入选关加载或主线。

实现时沿用原版 1600×900 坐标作为候选，但每一步必须有页面锚点和后置验证，不能只靠固定坐标。

## P2：主线稳定性

1. 把原版 `MonitorGameOver` 的 500ms 采样、灰度/5×5 模糊、差异阈值 15、差异像素不超过 500、连续静止 2 秒移植为“疑似结束”门闩。
2. 最终结算仍必须由胜利、失败或战后页面锚点确认，不能仅凭静止画面。
3. 补技能外的卡片、羁绊、宝物和黑商策略；策略未知时使用专用隐藏/放弃并验证面板消失。
4. 给四资源挑战的 `UNKNOWN` 状态增加总时限和明确诊断。

## P3：Boss、传家宝、秘境、龙珠

按“入口锚点 → 状态专用动作 → 后置状态 → 有界重试”逐项解封：

1. 存档挑战与配置 Boss（无配置时最后一个可用 Boss）；
2. 传家宝只左键 Boss 卡，禁止右键详情；
3. 大秘境满足全部地图挑战完成、无存活 Boss、英雄挑战锚点可见三项前置后再确认；
4. 龙珠按原版 7+19 模板组、计数、战斗判定和关闭链重建，不修补当前 legacy 占位类。

每一项都先加入同一个 `Mediator` 实例的时序回放，再开放真机输入。单帧模板命中或旧 `run_replay.py` 的绿色结果不作为“流程跑通”的证明。
