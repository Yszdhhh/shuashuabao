# 分辨率范围纠偏：首发只验收 1600x900

日期：2026-08-11  
状态：立即生效，覆盖旧蓝图和旧报告中的 960x540 强制门禁。

## 决策依据

游戏设置中的真实可选分辨率为：

- 1680x1050
- 1600x900
- 1366x768
- 1280x768
- 1024x768

游戏没有 960x540 选项。旧文档中的“每类至少 10 个真实 960x540 正面板”来自早期窗口尺寸/模拟帧假设，不是游戏真实支持的用户设置。

## 新的发布范围

1. 首个可用版本只支持并验收 `1600x900` 游戏窗口；
2. 960x540 状态从 `BLOCKED` 改为 `NOT_APPLICABLE`，不再阻塞 O3、O4、P0 或 R0；
3. 不采集、不缩放、不伪造 960x540 素材；
4. 1366x768、1280x768、1024x768、1680x1050 均列为后续兼容性扩展，不进入首发门禁；
5. 当前所有“长期无人值守”结论只允许限定为 `1600x900`；
6. 历史报告保留原始数字，但后续状态报告必须引用本文件，不能继续写“等待 960x540 用户素材”。

## 1600x900 的正确执行顺序

1. 修复 O4 压测 PASS 条件、R0 素材去重/内容验证、OCR 盲测口径；
2. 用现有 1600x900 录像和面板素材建立冻结的 end-to-end 回放集；
3. L0 局外流程真实 dry-run 20 次：建房、房名、密码、关卡 1-15、开始、回房；
4. 模板运行时先做监督实机 1 局，再做连续 3 局；
5. 接入 O4 shadow，只记录 1600x900 面板结果，不改变动作；
6. shadow 至少 100 个独立 panel episode 后，按技能、羁绊、宝物分别接入 P0；
7. 每类先监督 LIVE 30 个 episode，错误点击为 0 才开启下一类；
8. 再实施 G0 后段链路；
9. 最终执行 3 局、10 局、30 局/6 小时分级长稳。
