### 一、 核心架构审查检查点 (Checklist)

   - [ ] 检查混车模式（Hitch）是否严格执行「开局 20s 压力转移」检测；
   - [ ] 检查混车主线是否受主 C 进度从动约束（主线默认关，主 C 进层后再跟进）；
   - [ ] 检查战后判页是否使用了专有复合锚点（如 `cjbtiaozhan`、`mijingOk`），严禁单凭顶部共用 HUD 元素误判。

2. **L1 小机制原子红线**
   - [ ] 技能 G：是否强制限制 $\le 4$ 系？「蓄力射击」是否已列入 `never_pick`（-50% CD 负收益）？
   - [ ] 技能时序：是否彻底废除了旧版「积压 >= 8 强制抢占面板」的错误逻辑？确认技能点零囤积损失，仅在断崖质变点（23/30/46级）集中投入；
   - [ ] 羁绊 F：门卡 `gate_need=4` 规则与 1400 木/链预算是否正确注入；是否严格执行「高级组 base>=80% 且同时只推 1 套」；
   - [ ] 宝物 V：19 种负面 + 2 种存疑宝物是否在单源 Catalog 中默认强制拦截（跳过）；
   - [ ] 黑商 H：是否严格以杀敌数计价、执行 180s 免费冷却、且落实「刷新+购买 >= 440 杀敌」的两段式原子预算保护。

3. **L2 交叉约束与状态真源**
   - [ ] 资源三本账（木材=F/赌木，杀敌=黑商，刷新券=V/G/英雄）是否物理隔离？严禁跨币种臆造汇率折算；
   - [ ] 需求真源（Need）是否彻底剥离 UI 点击计数器？确认 Need 仅由静态 Catalog 与 Confirmed 持有数决定；
   - [ ] 互斥拓扑链是否严格执行：神兽(N12) -> 三国(9x3红卡) -> 龙族军团殿后；黄金猿上阵前装备必须处理完毕。

4. **L3 决策引擎与三类事实状态**
   - [ ] 决策调度器（如 `solo_scheduler.py`）是否保持纯函数、零副作用；
   - [ ] 三类事实严格隔离：Observed（见）、Requested（发）、Confirmed（定）。必须确保「唯有 Confirmed 方可推进卡牌持有与账本推进」。

5. **实机深水区机制补充审查**
   - [ ] **体术卡面**：确认按「斗气场域」80%力量自适应伤处理，严禁沿用过时“破甲10%”；

   - [ ] **高级组停滞熔断**：木材消耗超限（如 >2500木）仍卡手时，是否支持进入 STALLED 状态释放预算回退至基础属性链；
