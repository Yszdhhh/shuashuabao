# 原版 1.4.1 实机行为分析（Procmon + 录屏 + 日志三路，2026-08-10）

> 数据：Procmon CSV×2（53k/121k 事件）+ 原版 log.log + 录屏×2（2GB+2GB）+ 异常截图×13
> 结论供 GameScript-Local（前端）借鉴原版（后端）行为模式。

## 1. 原版架构（Procmon 证据）

- **单进程** .NET Framework 4.x，零子进程；依赖进程内 DLL
- **输入 = UIA InvokePattern 直调控件**（H.InputSimulator.dll 全部加载失败=从未使用）→ **选卡快的根本原因**：无需图像定位+鼠标移动，直接调控件方法
- **OpenCV 模板**：`OpenCvSharpExtern.dll` 本地 dll\x64\ 一次性加载；**276 图 0.237s 预加载进内存**，运行期零磁盘读（每图 3 次 ReadFile=OpenCV 解码）
- 模板目录：根 154（UI/按钮/状态）+ boss 52 + cards 36 + chuanjiaobao 17 + skills 16；**无羁绊目录** → 羁绊只选设定好的（模板缺失）
- 截图链路：System.Drawing + Media Foundation；配置：Settings.json 整文件重写（开局前/失败后）
- 网络：**纯心跳**（127.0.0.1:7897 15s 周期 17B/13B + NTP），绝非 AI 推理

## 2. 失败恢复模式（可借鉴）

```
失败 → 语义化截图留证（<100ms 写盘）+ log 追加 → 立即重试（不重读模板）
     → 恢复后 Settings.json 重写（状态持久化）→ 下一轮/下一局继续
```

- 失败恢复实测：21:47:08 声望挑战失败 → 46.9s 后自动恢复（保存配置×6+重验证环境）
- 截图命名语义化：startChallenge_fail / QuitGame / noBoss / no_cjb / no_click_yes_button / CaptureWindow
- **教训：无限重试无退出上限** —— 22:19:50-22:22:21 自动主线失败×7 仍"等下轮继续"；22:28-22:30 同一状态（提前挑战按钮）狂刷 40+ 次；失败局（大秘境杀敌不足）继续找龙珠 9.5 分钟不退出

- 进局：等退出→准备→开游→查找关卡（21:45:11→21:45:37）
- 选卡循环：间隔均值 20.4s（战斗期）→ 龙珠搜索期 9.2s（快一倍）
- 技能兜底：模板 miss → **F1 快捷键点击**（未检测到虚拟键盘）
- 锚点 Boss：局内解析 Boss 名=模板 stem（07大法师阿鲁高）→ 复位参照
- 龙珠7 搜索：200s 倒计时，**9.5 分钟不放弃不退出**（22:27:34 第二次找龙珠同样循环）

## 6. 用户观察对应

- "选卡快"：UIA 直控 + 模板预加载（两者都是架构优势，非单点技巧）
- "黑商/技能/羁绊/宝物都选得快"：同上 + 模板齐全（cards 36 + skills 16）
- "羁绊只能选设定好的"：模板无羁绊目录 → 原版羁绊识别弱；我们的羁绊按设定+品质降级（B4）优于原版
- "失败后没退出还在切卡片"：**无局内失败上限 + 状态机在失败态继续跑面板循环**（22:28-22:30 提前挑战狂刷 40+ 次的直接后果）
