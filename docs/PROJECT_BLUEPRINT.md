## 0. 现在的项目目标

第一目标不是继续增加玩法，而是把现有链路做成可验证的闭环：

```text
正确窗口
→ 有效截图
→ 正确场景
→ 安全候选
→ 目标窗口输入
→ 页面变化验证
→ 可恢复状态
```

第一阶段的可交付能力是：

```text
KK 地图页
→ 创建房间
→ 房间等待
→ 房间开始
→ 选关
→ 选中验证
→ 开始关卡
→ 局内选卡/挑战
→ Boss/龙珠
→ 退出
→ 下一局
```

任何无法确认窗口、帧、场景或动作结果的情况，都应该等待、重试或停止，不应该猜测点击。

## 2. 外部调研与原版迁移策略

当前研究结论先落到“策略数据”和“识别实体”，不直接写进状态机：

| 研究结论 | 工程落点 | 当前处理 |
|---|---|---|
| 已核实地图版本约为 1.1.89 | 资源包元数据、规则版本 | 记录来源，不覆盖当前客户端版本 |
| 奥术箭是资料最完整的首个流派 | `policies/arcane_arrow.json`、技能预设 | 作为第一套策略基线 |

| Boss、卡牌、技能、宝物、羁绊 | `entities` 数据和 OCR/模板词典 | 先标版本、来源、置信度 |
| 实战视频选择顺序 | JSONL 事件、真实回放夹具 | 未逐帧确认前不得作为训练标签 |

第一套策略只建议使用“奥术箭基线”进行验证：

```text
asj / asjg / assx / jq
```

但第一轮仍然只验证脚本稳定性，不同时实现赌木、黑市购买和自动合成。

### 2.1 原版参考迁移策略

原版 1.3.8 程序集（`GameScript.exe` / `GameScript.pdb`）已提取为完整的行为与安全迁移矩阵，详细内容参阅 [原版行为矩阵](ORIGINAL_1_3_8_BEHAVIOR_MATRIX.md)。工程迁移策略总结如下：

1. **原版作为行为与模板参考**：原版已有的“状态识别 → 配置项 → 决策 → 动作 → 后置状态/超时”逻辑作为功能与模板特征词典参考，不盲目从零设计状态机。
2. **保留 P0-A 安全执行链**：新工程严格保留 HWND 绑定、窗口身份校验、帧健康检查、全局急停与真实输入封锁，绝不直接使用原版的裸 Win32 / WinForms 输入调用。
3. **当前截图用于版本差异验证**：`fixtures/reborn_wow/` 中的全屏截图是当前版本界面识别与 Dry-run 回放的唯一权威来源，旧版小模板仅用于特征命名比对。
4. **四步推进闭环**：后续所有功能按“**原版行为提炼 → 当前 UI 截图验证 → 安全迁移 → 回送 Replay 验收**”的标准顺序推进。

## 7. 交付与验收审查规程

每个 Agent commit 都按以下顺序验收：

1. 检查 diff 是否只包含任务范围，是否新增不必要依赖。
2. 运行 `compileall`、全部 `unittest` 和 `tools/validate_scenes.py`。
3. 检查配置默认值、Dry-run、停止逻辑和异常路径。
4. 运行真实截图回放，检查检测框、分数、点击点和禁点结果。
5. 对危险动作做负样本回放：快速加入、取消、退出、助手窗口、黑帧和冻结帧。
6. 检查动作是否有前置证据、目标 HWND、后置证据和恢复路径。
7. 给出“通过 / 有条件通过 / 退回修改”的验收报告。

只有 P0-A 和 P0-B 都通过，才进入关闭 Dry-run 的短步数实机验证；只有稳定回放和实机短跑通过，才开始接入黑市、赌木、隐藏合成和多流派策略。
