# 原版参考脚本架构与去僵化重构指引 (Reference Architecture & De-Rigidization Guide)

## 一、原版参考脚本位置与基线事实
- **原版可执行程序**：`G:\下载\刷刷护肝宝65.exe` / `G:\下载\1.4.7.zip\1.4.7`
- **原版反编译与矩阵文档**：`docs/ORIGINAL_1_3_8_BEHAVIOR_MATRIX.md`
- **核心差异总结**：

| 对比维度 | 原版 1.3.8 / 1.4.7 设计哲学 | 当前重构版 (过度防御) | 改造目标 (去僵化) |
| :--- | :--- | :--- | :--- |
| **推进哲学** | **界面状态驱动 (State Alignment)**：只要处于该界面，就持续按节奏探测并推进动作 | **微观计数驱动 (Micro-Attempts)**：每个动作硬编码 `attempts < N`，一旦超限立刻自杀报错 | 改回**界面状态自愈驱动**，只保留宏观超时与画面停滞检测 |
| **选关策略** | 滚轮下滚 -> 找目标 -> 没找到继续下滚 -> 到底/超时 -> 选中目标进入 | 滚 8 次（现改 25）必须找到，超限直接 Phase.ERROR 退出 | 持续下滚直到目标出现或检测到滚动条到底 |
| **选卡策略** | 弹出选择界面 -> 匹配目标 -> 匹配不到或无按钮保持安全观察/选择默认卡 | 匹配不到硬刷 -> 没刷新按钮卡死 900 秒 | 无安全候选且无刷新时，直接点关闭或品质保底，绝不挂起 |
| **容错机制** | 弹窗动画延迟/鼠标事件被吞，下一 tick 自然重试 | 第一次点击后将标志位锁死为 True，导致永久死等待 | 允许失败自愈重试（如建房 4s 无弹窗自动补点） |

## 二、给云端 AI 审查与重构的关键任务
1. **清理 `mediator.py` 中的生硬微观预算**：
   - 检查所有 `_attempts < N`，凡是不涉及真实安全红线的微观计数器，统一改为“基于当前界面的持续自愈推进”；
2. **保留且仅保留两类宏观保护**：
   - **宏观阶段超时**：如选关最多停留 60s、单局最多 900s、建房最多 30s；
   - **物理停滞检测**：连续 N 帧画面完全无变化且无任何交互响应时才报警停机。
