# 蹭车链路全面审计：长期无输入与冲突（2026-09-12）

范围：`src/shuabao/mediator.py` 蹭车（`mode_id=lobby_hitch`）全链路 —— 大厅找房 → 进房/准备/座位规则/退房 → 进局（压力转移、自动任务、四挑战、背包）→ 战后 → 失败恢复 → 退出 → 回大厅。基线 6556f63，本轮改动见文末。

## 1. 为什么会反复出现「脚本长期无输入」

近 5 次实机事故（黑窗口 275s、升房主后点头像、换肤房间 7min、压力转移门禁整局零输入、失败页被聊天条挡住）根因各不相同，但**形状完全一样**：

1. 某个局部处理器进入「等证据」分支，返回 `Continue` 且不发输入；
2. 它等待的证据由**另一个阶段**负责产生，或者画面已经变成别的阶段的画面（游戏窗已在跑 / 失败页 / 房间已关）；
3. 局部分支没有上限，或上限到期后「重新武装并继续等待」；
4. 于是阶段与真实画面长期错位，没有任何代码负责把两者对齐。

统计（本轮基线）：`mediator.py` 中带「零输入/零动作」日志的返回分支 165 个，其中蹭车/乘客相关约 60 个；「预算耗尽 → 重新武装继续等待」的乘客分支 6 个（战后继续 ×2、存档面板关闭、传家宝弹窗关闭、局内退出按钮、退出确认），另有「暂停恢复 5 次后保持零输入」「未验证战后入口保持观察」「未实现战后页面零输入等待」「表面冲突持续零输入」「战后转场超时继续等待」。

逐个给这些分支加超时只能治标：每修一个，下一次实机又会从另一个分支卡住。

## 2. 通用方案：单一的无进展监督（liveness supervisor）

`Mediator.tick()` 在 `_tick_impl()` 返回 `Continue` 后执行 `_hitch_liveness_supervise()`（仅蹭车 LIVE；dry-run/OBSERVE、非蹭车模式不启用）。局部处理器照旧可以零输入等待，监督器只规定**最长能等多久**，以及到期后如何处理。

### 2.1 进展的定义

- 本 tick 有一次成功输入（`_tick_input_executed`）即为进展，梯级清零。
- 盲按键不算进展：`HitchStallWatchdogEsc`（UNKNOWN 兜底 Esc）、`HitchLeaveMisopenedStage`（QUIT 选关页 Esc）。
- 设计内、自身有上限的零输入等待可以声明截止时间（`_hitch_declared_wait_until`），预算从截止时间之后开始算。当前只有找房循环耗尽后的 120s `SLEEP_RETRY`，这是审计发现的真实冲突：否则 90s 大厅预算会打断设计好的休眠。

### 2.2 预算（无有效输入）

| 阶段 | 预算 | 依据 |
|---|---|---|
| LOBBY_ROOM | 90s | 刷新 5s 一次；进房确认、导航、Tab 都是秒级 |
| ROOM_WAITING | 180s | 准备后等 70s + 超时退房 30s + 宽限 60s = 160s |
| MAIN_LINE | 180s | 乘客局内有黑商/背包/15s 活性步进 |
| RECOVER_FAILURE | 90s | 每步确认窗约 5s |
| QUIT / NEXT | 60s | 单步观察窗 15s |
| 其他 | 150s | — |

### 2.3 梯级

到期时先**读取真实画面**（`_hitch_observe_world`：英雄三国窗口优先，其次 KK 窗口），不信任当前阶段：

| 画面 | 归属阶段 |
|---|---|
| 游戏失败/断线页 | QUIT（`_recovery_step=DONE`，走左上角退出） |
| 游戏选关页（误开） | QUIT |
| 局内 HUD / 战后页 | MAIN_LINE（有准备记录走自然进局初始化） |
| 游戏内等 1 号位选难度 | ROOM_WAITING |
| KK 房间 | ROOM_WAITING |
| KK 大厅房间列表 | LOBBY_ROOM |

1. **第 1 级 校正/软复位**：画面属于别的阶段就移交过去（从局内阶段回到 KK 阶段时清掉旧局瞬态，不计局数）；已在正确阶段则软复位该阶段的瞬态（大厅：新搜索状态机 + 导航复位；局内：面板 FSM、待确认动作、背包 FSM、黑商循环、自动任务复查、聊天条与暂停恢复预算；退出链：尝试计数；房间：座位复核）。QUIT/NEXT 看到任何游戏画面一律回 QUIT（重新点退出按钮，而不是回到局内）。
2. **第 2 级 离开**：游戏画面 → QUIT 退出游戏；KK 房间 → 走房间自带的有界退房事务（`_hitch_ready_timeout_pending`，Esc + fresh 大厅证明，宽限期后 BLOCKED）；其他 → 重置回大厅重新找房。
3. **第 3 级 BLOCKED**：`ERROR` + stop + incident（`hitch_liveness_stall_l*`），明确停机而不是无声挂住。

**正在进行的局**（MAIN_LINE 且画面是局内 HUD）只做软复位、不升级，因为乘客在局内合法挂机很常见；整局由 hard deadline（`round_timeout_s`，默认 3600s）兜底。附着进来的局（非自然进局、跳过了新局初始化）原本没有 deadline，现在由监督器补上。

### 2.4 活锁（一直在点但不推进）

零输入梯级看不到「一直在点」的循环（例如：点退出 → 确认框不出现 → 回 QUIT 再点退出 → …）。同一监督器按阶段族限制总停留时间，无论是否有输入：

| 阶段族 | 上限 | 到期处理 |
|---|---|---|
| 退出链 QUIT+NEXT | 240s | BLOCKED |
| 失败恢复 | 180s | 游戏画面 → QUIT，否则 BLOCKED |
| 房间 ROOM_WAITING | 600s | 先离开一次（退房/退游戏），再到期 BLOCKED |

大厅找房（可以无限搜索）与进行中的局（由 hard deadline 限制）不设停留上限。

### 2.5 可观测性

trace `hitch` 字段新增 `stall_s`（距上次有效输入的秒数）、`stall_level`；每次升级打印「实际画面=…」并留 incident 截图。
