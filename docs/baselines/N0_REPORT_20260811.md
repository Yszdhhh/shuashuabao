## 3. 实现摘要

### 3.1 benchmark_hot_path.py

- 每 fixture 帧按 **cold / warm-changed / exact-static** 三模式各跑 N 次（默认 3）：
  - cold：清模板缓存 + 新 Mediator → 含模板解码/缩放；
  - warm-changed：模板缓存热 + 新 Mediator + 新帧对象 → 全量重扫（镜像生产变动帧）；
  - exact-static：同一 Mediator + 同一帧对象 → context 缓存命中、scene 缓存按 see()
    语义每 tick 清空后重建（镜像生产静态帧路径）。
- 分阶段计时：capture（帧解码代理）/ health / context / decision / action；
  健康门禁镜像 `_tick_impl`（frozen/old_frame 放行，其余不健康跳过决策）。
- action 阶段为 dry-run 分派开销（InputExecutor DRY_RUN 零等待零输入，P50≈0）；
  生产真实输入另有固定成本：鼠标移动/点击约 390ms 内部等待 + click_delay 120ms
  （§3 已知项），不属本基准测量范围。
- 进程内包装 `cv2.matchTemplate` 计数调用次数与搜索像素总量。
- 记录环境（Python/OpenCV/CPU/分辨率/commit）+ assets/Images 模板聚合 SHA256。
- 输出 docs/baselines/N0_BENCHMARK.json + .md；同一命令可重跑。
- 实时捕获参考段（可选）：本机无游戏窗口时以全屏 mss 抓取为参考（P50≈26ms）。

## 8. 风险与回滚

- 风险 1：基准对机器负载敏感（实测 DATA 1fps 扫描期间慢 ~4.5×）。对策：三次基准
  在协调的安静窗口内运行；报告记录负载环境。
- 风险 2：断线类 fixture 缺失，S0 实现前需补充素材（本波以 missing 记录）。
- 风险 3：5fps 分辨率 0.2s 决定延迟精度下限；点击位于观测帧前 ≤0.2s 内，latency
  为保守上界。
- 回滚：全部为新增文件，删除 tools/benchmark_hot_path.py、tests/performance/、
  docs/baselines/N0_* 即回滚；无生产代码改动。
