## 0. 方法与时基

- 时间换算：录屏相对时间 = trace ts − (录屏 mtime − 录屏时长)。三局偏移均经 trace 起始帧画面（KK 平台大厅/创房弹窗）视觉校验通过：
  - 164929 ↔ trace_165946：偏移 **+102.5s**（trace 相对 0s = 录屏 102.5s）
  - 205044 ↔ trace_205100：偏移 **+16.6s**
  - 215302 ↔ trace_215307：偏移 **+6.3s**
- 抽帧纪律：全部按 trace 定位事件窗后 5fps 抽帧（`-threads 2`，顺序、一次一段），未做全量抽帧；视觉判定由 4 个 vision/designer 子 agent（gemini）完成，关键几何（按钮位置/尺寸/颜色分量）由 OpenCV 在原始帧上复核。
- 三局初始 51~52s 零动作窗（tick 10→~158）均为**正常进房加载**（反作弊倒计时 → “正在进入游戏…” → “等待玩家中 100%” → “加载地形数据 47%” → 选关页），不是卡死。

**当前代码复核与修复建议**：

## 4. 三局共性

1. **没有任何一局是游戏崩溃/黑屏/白屏**：三局画面全程有内容，卡死均为“脚本逻辑停滞”（假命中循环 / 恢复 0 输入 / 面板无法分类），Fail-Closed 行为（宁可停不盲点）与设计一致。
2. **初始 51~52s 零动作窗都是正常加载**，不可当作卡死。
3. 两处“可见即不可检”问题（164929 进化按钮 vs 模板、215307 面板按钮 vs 锚点模板）指向同一根因：**模板资产与真实 UI 布局漂移**（同游戏不同英雄/面板布局，模板 0.70~0.85 贴阈值）。
4. 失败/选择面板的“后置确认”与“真实素材回归”缺口：205044 失败弹窗、215302 羁绊面板均可直接作为回归素材，缓解 handoff 中两个 XFAIL（`fail_recovery_three_frames`、`ticket_zero_archaeology` 之外的面板类缺素材问题）。
