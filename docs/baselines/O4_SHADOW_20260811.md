# O4 OCR Shadow Sidecar — 2026-08-11

## 1. 结论

O4 独立 shadow 模块已实现，未接入 `mediator.py`。主进程只导入 JSONL/client 协议和图像编码代码；Paddle/PaddleOCR 仅在 `.venv-ocr` 持久子进程中加载。返回值只有规范候选、置信度和耗时（不可用时为 `unavailable`），模块没有输入执行路径。

## 2. 文件

- `src/gamescript/vision/ocr_shadow/protocol.py`：JSONL 编解码、`ShadowResponse`、panel 内容指纹。
- `src/gamescript/vision/ocr_shadow/client.py`：常驻 `Popen`、顺序请求、心跳、超时、崩溃重启上限、面板指纹缓存、独立 shadow trace。
- `src/gamescript/vision/ocr_shadow/worker.py`：sidecar 入口；本地模型校验、ASCII staging、一次模型加载、归一化候选。
- `tools/ocr_sidecar_stress.py`：10,000 请求/三槽 P95/RSS 曲线/子进程/协议对齐压力工具；PASS 只允许真实模型场景，缺失/损坏模型使用独立 `--scenario degraded` 报告。
- `tools/ocr_sidecar_ledger_check.py`：off/shadow 两模式 replay action ledger 等价校验（复用 compare_ledger 规则）。
- `tests/test_ocr_shadow.py`：协议往返、坏 JSON、超时、崩溃重启、缓存失效、模型缺失/损坏降级。
- 证据：`docs/baselines/O4_STRESS_REAL_20260811.json`（10k 真实推理）、`docs/baselines/O4_LEDGER_20260811/{off,shadow}.jsonl`。

## 3. 协议

每条 stdin 请求一行 JSON；sidecar 每条 stdout 响应一行 JSON。客户端按 `seq` 严格匹配，服务进程按顺序处理。

```json
{
  "type": "predict",
  "seq": 12,
  "frame_ref": "1600x900:md5...",
  "session": "rec5_260808",
  "panel_id": "panel-42",
  "slot_id": 1,
  "id": "panel-42:1",
  "bbox": [640, 210, 920, 315],
  "kind": "skill",
  "image_b64": "<PNG crop>",
  "sent_at": 1786430000.12
}
```

可用响应：

```json
{"seq":12,"status":"ok","candidates":[{"name":"奥术增幅β","confidence":0.91}],"elapsed_ms":142.7}
```

不可用响应：

```json
{"seq":12,"status":"unavailable","candidates":[],"elapsed_ms":400.0,"reason":"timeout"}
```

`reason` 可为 `starting`、`timeout`、`bad_json`、`crash`、`model_missing`、`model_corrupt` 或 `inference_error`。坏 JSON、超时和子进程 EOF 会杀掉当前管道；下一请求使用新管道，避免迟到响应造成协议错位。连续崩溃达到 `max_restarts`（默认 3）后，本次 session shadow 禁用；`reset()` 可显式开启新 session。

启动握手（sidecar 启动后首行，seq=0）：

```json
{"type":"ready","seq":0,"status":"ok","candidates":[],"elapsed_ms":0.0,"load_ms":6073.4,"model_validated":true}
```

`load_ms` 为模型加载耗时；`model_validated=true` 表示 manifest 中 3 个文件的 SHA-256 与 size_bytes 全部实测通过后才加载（staging 后再次校验）。

## 4. 模型与离线行为

worker 只读取 `models/ocr/PP-OCRv5_mobile_rec_infer`，启动前校验 manifest 中的文件大小/SHA-256，并复制到 ASCII 临时目录以满足 Windows Paddle loader 限制。不存在、损坏、无法加载的模型不会传播异常；worker 保持 JSONL 服务并对每个预测返回 `unavailable`。主进程不 import `paddle`，也不发起下载。

## 5. 缓存与 shadow 边界

缓存结构为 `panel_id -> (panel_fingerprint, slot+bbox+kind -> ShadowResponse)`。新 fingerprint 会立即清空该 panel 的旧槽结果；面板缓存最多 256 个 panel，避免画面轮换导致增长。缓存只返回候选，永不授予动作授权。`ShadowClient` 仅写可选的独立 JSONL trace（`trace_path`），包含 fingerprint、bbox、状态、候选、耗时和 `cache_hit`。

## 6. 接线接口

集成波使用：

```python
from gamescript.vision.ocr_shadow import ShadowClient

client = ShadowClient(timeout_ms=400, trace_path="logs/ocr_shadow.jsonl")
response = client.shadow_predict(
    frame,
    panel_id,
    {"slot_id": slot.index, "bbox": slot.bbox, "kind": panel_kind},
    session=session_id,
    panel_bbox=panel_bbox,
)
# response.status == "ok" 时读取 response.candidates；不产生任何输入动作。
```

也提供 `shadow_predict(frame, panel_id, slot, client=client)` facade。集成方负责在强面板锚点成立且模板低置信/unknown 时调用；普通 tick 不调用。模板决策和 action ledger 仍是唯一动作来源。

### 6.1 O4 stress 全字段硬门禁

`tools/ocr_sidecar_stress.py` 的 `pass` 由 `hard_gates` 全部通过才成立；任一项失败时进程退出码为 1，并在 JSON 的 `gate_failures` 及 stdout 逐项列出 `FAIL` 明细。真实模型门禁为：

| 门禁 | 硬阈值/规则 |
|---|---|
| `model_validated` | 必须为 `true`；worker 启动握手已完成 `MODEL_MANIFEST.json` 三文件 SHA-256 + `size_bytes` 校验（ASCII staging 后再次校验） |
| `unavailable` | `0` |
| `worker_restarts` / `protocol_errors` | 均为 `0` |
| RSS 峰值 | 全部采样（含起始/结束）峰值 `≤2048.0 MB`（2.0 GiB 十进制报告值） |
| RSS 平台化 | 10,000 请求必须观察 `i=4500` 至结束的 5,500 请求尾段；尾段结束增量及尾段最大增量均 `≤128.0 MB`。全程 `rss_delta` 不作为唯一判据，以区分 Paddle CPU 池预热增长和泄漏 |
| 时延 | 单槽 P95 `≤120.0 ms`；三槽 panel P95 `≤300.0 ms` |
| 进程/缓存 | `max_child_processes ≤1`、worker 退出且无残留子进程、`cache_panel_bound=true` |

`rss_gate` 固定输出阈值、`peak_mb`、`plateau_start_mb`、`plateau_end_mb`、`plateau_delta_mb`、`plateau_max_delta_mb` 和 PASS/FAIL 字段，不隐藏测量区间。`--scenario degraded` 仅用于 `model_missing`/`model_corrupt` 独立降级证据，强制非 PASS，不得并入真实模型主报告。

## 8. ledger 与风险

本波只新增独立 OCR runtime、压力工具、单测和本 baseline 文档；没有修改 `mediator.py`、场景、设置、输入执行器或 action ledger。`ocr_mode=off` 与 `ocr_mode=shadow` 的 replay action ledger 逐字段等价（32 行 × 0 diff），证明 shadow 无输入动作权、尚未接线。OCR 结果只能进入 shadow trace；接线波必须继续保持 off/shadow 与模板 action ledger 等价，并把首次模型 warmup 期间（实测 6.1-7.7s）的 `starting` 当作 unavailable。

风险登记：
- sidecar 稳态 RSS ~1.65GB（Paddle CPU 内存池，有界、与 O3 评测同源行为）；仅影响 sidecar 进程，不影响主进程。
- 干净环境时延门禁为单槽 P95 ≤120ms、三槽 panel P95 ≤300ms；CPU 争用时单次推理可能超 400ms timeout 并触发重启，重启 warmup 期间 shadow 返回 unavailable（不阻塞主 FSM，但候选短暂缺失）。
- 首次请求在模型 warmup（~6-8s）完成前返回 `unavailable/starting`；集成方应把该 reason 与 `model_missing` 同等对待（只影响 shadow，不影响模板动作）。
- 960×540：`NOT_APPLICABLE`（游戏无该真实分辨率，见 `docs/SCOPE_OVERRIDE_1600X900_20260811.md`）；断线素材与实机恢复仍未验证，O4 不构成生产接线放行条件。
