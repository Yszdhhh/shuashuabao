## 3 项 FAIL 的 waiver 根因（RUNTIME-2 实证）

1. **changed idle 467ms（门禁 400）**：每 tick 保留 archive/boss/longzhu Fail-Closed 检查 ~225ms（boss 全帧灰度 ~90ms + longzhu 色相彩色 ~115ms + archive ROI ~20ms）。曾尝试以 in-game HUD 证据短路——victory fixture 实证 HUD 元素（skillchallenge 0.92）可与战后模态共存、p1a2/p0c1 安全测试要求首 tick Fail-Closed，**已回退为每 tick 全量检查（安全契约优先）**。
2. **unknown_page 627ms（门禁 500）**：同上 + ctx 级联全 miss。
3. **cold preload 483ms（门禁 250）**：加载开销 ~30ms，剩余为首 tick 扫描耗时。

**S0 复评项**：S0 引入明确 Phase 管理后，archive/boss/longzhu 检查按阶段条件触发（如 LONGZHU 阶段才查 longzhu 色相），预期 idle/unknown/cold 三项达标；复评后撤销 waiver。

## 灰度方案（N2.4）

- 模板灰度加载时一次转换缓存；Frame.gray() 每帧一次，同帧灰度模板共享
- 形状/文字类：灰度候选（阈值=彩色阈值-0.05，218 样本差中位数 0.000/P90 0.017/max 0.058）→ 候选局部 ±1px numpy 彩色 NCC 复核（原彩色阈值），复核不过=假阳性否决；复核不增 matchTemplate 计数
- hue 模板（longzhu 蓝框、稀有度/品质色）保持纯彩色
- 同图多名按内容 MD5 去重（kk_start/room_start 等 5 图字节相同，25→5 次扫描）
