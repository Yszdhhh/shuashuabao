# 大厅 / 房间层缺口说明（外部 Agent 必读）

> 用户核心投诉：开着脚本站在**自己建好的房间**里，脚本一直跑但**不点「开始游戏」**；  
> 联网官方版却会**建房、设密码、开始**。  
> 结论：**不是“全坏了”，是识别范围分层 + 模式语义 + 本地未实现房间层。**

---

## 1. 两层世界（最重要）

```
┌─────────────────────────────────────────────────────────┐
│  L0 游戏外 / 大厅 / 房间（Lobby · Room）                  │
│  · 创建房间 · 房间名/密码 · 等人 · 点「开始游戏」           │
│  · 官方方法：CreateRoom / BeginGame / LaunchGame / Entry │
│  · 模板极少：startGameBtn / jihuo / continueGame（且易失效）│
└───────────────────────────┬─────────────────────────────┘
                            │ 进入对局加载成功后
┌───────────────────────────▼─────────────────────────────┐
│  L1 局内 / 选关后 / 战斗中（In-Game）                     │
│  · 选关 · 选卡 · 技能 · 龙珠 · Boss · 秘境 · 退出         │
│  · 模板主体都在这里（Images 里 90%+）                      │
│  · 日志：开始主线 / 卡都找完了 / 锚点Boss / 找龙珠 …      │
└─────────────────────────────────────────────────────────┘
```

**本地恢复与外部 Agent 一直在做的，几乎全是 L1。**  
**L0 在官方 exe 里有（CreateRoom 等），但：**

1. 模板包里**几乎没有**「创建房间 / 输入密码 / 房间列表」完整图集  
2. 本地 `mediator.py` **没有** CreateRoom / 房间态状态机  
3. 官方帮助对 **独狼** 写的是：**自己点房间开始**（见下）

所以：你站在房间里不动 → 脚本在等 L1 的「关卡/主线 UI」→ 日志长期停在 **「等待进入游戏UI」** → 看起来像“一直跑但不点开始”。

## 2. 官方模式语义（帮助原文逻辑）

文件：`1.3.3.3/使用前阅读.html` / `docs/使用前阅读.plain.txt`

| GameMode | 名称 | 房间/开始行为 |
|----------|------|----------------|
| **0 独狼** | 单人 | **自己点击房间开始游戏**；队友不卡房也可以组队用此模式 |
| **带队/车头** | 队长 | 用房间**自动开始**；**不会主动点开始** |
| 赌木 | — | 只开主线+第一宝物… |
| 邪修秘境 | — | 其它功能关，只打 Boss |

房间名 / 密码 / **每局新房间**（`RoomName` `RoomPassword` `NewRoomEveryTimes`）：

> **仅带队模式有效**

用户当前配置（核查时）：

```
GameMode = 0          ← 独狼
RoomPassword = 111
NewRoomEveryTimes = True   ← 独狼下官方说明为“仅带队有效”，易误导
```

**因此：独狼 + 自己建好房坐着等脚本点开始 = 与官方文档设计不一致。**  
联网版你印象中的「自动建房+密码+开始」来自 **带队/CreateRoom 流程** 或当时模式不是纯独狼，**不是** L1 选卡那套逻辑。

## 3. 官方日志里 L0→L1 长什么样

### 能进局时
```
验证环境成功，准备开始游戏
等待所有人退出游戏状态！
开始游戏或开始准备游戏
已经准备游戏了
等待进入游戏UI          ← 已离开“纯房间闲置”，在等选关/主线
开始主线！              ← 进入 L1
卡都找完了！…
```

### 卡在房间/没进选关时
```
验证环境成功，准备开始游戏
等待进入游戏UI
…（空等 ≈ QueryTimeOut 秒，默认 120）
ERROR 未找到关卡/主线UI,未找到位置
```

注意：失败时**往往没有**「已经准备游戏了」或有准备了但**从未「开始主线」**。  
说明卡点在 **L0→L1 门槛**，不是选卡/技能。

| 文件 | 用途猜测 | 问题 |

| `startGameBtn.png` | 开始游戏 | 与游戏内蓝按钮匹配分常很低（曾 ~0.4），**经常点不中** |

## 6. 用户正确用法（现在立刻能用的）

### 方案 A — 继续用官方联网 exe（推荐先稳定刷）
1. 确认模式：要自动建房/密码 → 用**带队**相关模式，并填房间名密码；  
   独狼 → **你自己点房间「开始游戏」**。
2. 分辨率 1600×900，缩放 100%。
3. 点开始后进到**选关页或进局**，脚本才会「开始主线」。
4. 脚本窗不要挡住游戏。

### 方案 B — 本地工程要补的功能（给开发/Agent）
1. 新增状态：`LOBBY_ROOM`（房间内）  
2. 用户提供/截取当前客户端「开始游戏」按钮模板 → `assets/Images/lobby/`  
3. 独狼：在房间内循环匹配并点击开始  
4. 带队：另做 CreateRoom（需更多 UI 模板与输入），**当前明确后做**  
5. 日志打印：`[L0] 检测到房间，尝试点击开始` / `[L0] 未找到开始按钮模板`

## 8. 已实现 / 如何截模板（P0 验收）

### 已实现内容

1. **L0 状态机**：`mediator.py` 新增 `LOBBY_ROOM` 相位，独狼模式下脚本在房间内能自动循环识别并匹配点击「开始游戏」按钮。
2. **场景配置**：`config/scenes.json` 新增 `lobby_start` 节点与 `priority` 优先序。
3. **模板目录**：`assets/Images/lobby/room_start.png` 已补齐；与根目录旧模板兼容。
4. **日志规范**：输出明确的前缀日志：
   - `[L0] phase=LOBBY_ROOM`
   - `[L0] match room_start score=0.xx @ (x,y)`
   - `[L0] click start`
   - `[L0] → WAIT_UI`
   - `[L1] 开始主线 / phase=MAIN_LINE`
   - `[L0] miss lobby start，请确认在房间界面或更新模板`

### 进入游戏后无法选关的修复

现象的直接原因是运行截图常为 `1936×1066`，而模板按 `1600×900` 截取；旧版只做 1.0 倍匹配，`stage.png` 实际得分约 `0.65`，因此被 `0.85` 阈值过滤。现在仅对 L0 开始按钮与 L1 选关标识启用 `0.9/1.0/1.1/1.15/1.2` 多尺度匹配，并移除全屏截图兜底，避免误点桌面。

> 边界：多尺度修复证明了缩放漏检会被修复，但当前 `room_start.png` 仍沿用旧的 `startGameBtn.png` 内容，尚未有真实 KK 房间截图回归样本；`stage1/stage2` 目前也只显示在运行配置中，尚未用于限定具体关卡编号。因此这次修复解决的是“看得到并尝试点击”的识别链路，不承诺自动选到配置范围内的精确关卡。
> `WAIT_UI` 点击开始后不再盲点同一按钮；若页面没有变化，会等超时回到 `LOBBY_ROOM` 重试。找不到目标窗口时只返回黑帧，不再截取桌面。

### 如何截取/更新模板

若界面皮肤更新或分辨率渲染有微调导致 `miss lobby start`：
1. 将游戏/平台窗口调整为 **1600×900** 窗口化（缩放 100%）。
2. 在房间界面用截图工具精确裁切「开始游戏」按钮图块（仅含按钮文字与边缘）。
3. 保存为 `PNG` 格式并覆盖 `assets/Images/lobby/room_start.png`（也可添加 `room_start_alt.png`）。
4. 若只卡在选关，优先确认截图中能看到关卡卡片/`1-1` 等标识；日志应出现 `[L0] 选关 SelectStage` 或 `[L1] 局内选关 SelectStage`。
