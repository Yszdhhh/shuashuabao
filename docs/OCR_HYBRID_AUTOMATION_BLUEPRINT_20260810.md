# GameScript-Local 混合识别与长期无人值守改造蓝图

> 日期：2026-08-10  
> 用途：直接拆给 Coding Agent 执行；项目负责人按本文逐阶段验收。  
> 范围：当前仓库的模板识别 + 定点 OCR 异常兜底 + 确定性决策 + 多局稳定性。  
> 不包含：读取游戏内存、DLL 注入、网络协议修改、全屏端到端大模型控制。

## 1. 结论与目标

本次不重写现有自动化。目标是在当前安全状态机上增加一层很薄的“结构化观测”，解决技能、羁绊、宝物文字变化和版本更新后模板缺失的问题。

目标链路：

```text
现有窗口捕获
→ 现有模板/颜色/几何判定
→ 仅在明确弹窗或异常时裁剪固定 ROI
→ OCR 识别选项文字
→ 词典归一化
→ 纯规则决策
→ Mediator 仍是唯一调度者
→ InputExecutor 仍是唯一输入出口
→ 后续帧确认动作生效
→ 失败时等待、关闭面板、保存证据或停机
```

最终产品门槛不是“单局能跑”，而是：

- 配置外技能误选为 0；
- 禁止区域/错误窗口输入为 0；
- 选择弹窗不能无限卡死；
- 累计至少 100 局、12 小时，且包含一次至少 6 小时连续无人值守；
- 任何未知页面都能留下可复现证据；
- 新版失败时可以一键退回当前稳定版。

当前事实：

- `Mediator` 约 2854 行，已经同时承担分类、时序、规则、执行和恢复；不得继续把 OCR 细节直接堆进 `_tick_main_line()`。
- 当前约 316 张运行模板、85 张 fixture 图片、6 个时序场景、19 个测试文件。
- 当前工作树有大量尚未提交的稳定性修复；任何 Agent 开工前必须先固化基线，禁止 reset、checkout 或覆盖用户改动。
- 当前回滚版是 `dist_release2/GameScript/GameScript.exe`；不得覆盖、移动或重打同名目录。
- 桌面版目前没有调用 `Mediator.set_trace()`；命令行/API 有 trace，桌面实机却缺少完整 tick 证据，这是第一项基础缺口。
- 当前 `.venv` 是 Python 3.11，但没有 `pip` 模块；B0 测试仍可用它执行，B2 不得为了试 OCR 依赖而改坏这个现有运行环境。
- 本机为 i5-13600KF、RTX 3070 8GB、Windows 10。OCR 首版仍以 CPU 定点推理为基线，GPU 只能是可选加速，不能成为部署前提。

## 3. 不可破坏的安全不变量

所有阶段、所有 Agent、所有提交都必须满足：

1. 每个 tick 最多一个真实输入动作。
2. 所有输入仍经 `InputExecutor`；OCR 模块、策略模块不得直接点击或按键。
3. OCR 结果不提供任意坐标，只能返回已验证槽位编号或页面辅助证据。
4. 只有现有页面锚点/布局先确认后，才允许裁剪该页面的 OCR ROI。
5. 禁止全屏无约束 OCR，避免聊天、任务文本、直播字幕污染判断。
6. 不健康帧、错误 HWND、前台窗口不符、急停触发时，OCR 和模板结果都无动作权。
7. 技能只允许选择用户配置项；未命中时刷新，刷新用完后放弃。永不按稀有度补选技能。
8. 羁绊、宝物可以按预设、合成进度、品质、用户偏好降级；至少一个槽位未被验证时不得盲点固定坐标。
9. OCR 兜底动作必须经过连续两帧一致或等价的稳定性确认。
10. 点击成功不等于业务成功；必须由后续帧确认面板关闭、候选变化、按钮状态变化或资源变化。
11. `ocr_mode=off` 时，动作序列必须与当前基线一致。
12. `ocr_mode=shadow` 时，OCR 只能记录建议，动作序列必须与当前基线一致。
13. 未知页面不得无限等待：有界等待后保存证据；LIVE 模式按页面危险度安全关闭或 Fail-Closed。
14. 不在运行时联网下载模型；所有模型文件本地固定版本、固定哈希。
15. 不覆盖 `dist_release2`；每阶段构建输出独立目录并可直接回滚。

## 4. 目标模块边界

只新增必要模块，不建立通用 AI 框架。

### 4.1 建议新增文件

```text
src/gamescript/vision/choice_ocr.py
    只负责：固定 ROI 裁剪、OCR 推理、词典归一化、输出 ChoiceObservation

src/gamescript/choice_policy.py
    只负责：根据结构化候选和设置做纯函数决策，不截图、不点击

config/choice_lexicon.json
    技能/羁绊/宝物规范名、别名、常见 OCR 混淆、类别和版本

tools/evaluate_choice_ocr.py
    离线评测真实截图，输出 JSON/Markdown 指标与错例

requirements-ocr.txt
    OCR 依赖单独管理；通过离线门禁前不并入桌面 requirements

fixtures/ocr_choices/
    OCR 原始裁剪、标签和来源清单；按采集会话划分训练/验收集
```

不要创建 `providers/`、`factories/`、插件框架、通用 DAG、消息总线或数据库。只有一个生产 OCR 实现时，就写一个实现。

### 4.2 最小数据契约

```python
ChoiceSlot:
    index: int                  # 0/1/2，不能是任意屏幕坐标
    click_point: tuple[int,int] # 由已验证面板几何生成，客户区坐标
    raw_text: str
    normalized_name: str | None
    ocr_confidence: float
    lexicon_margin: float       # 第一/第二词典候选分差
    rarity: str | None
    set_progress: tuple[int,int] | None

ChoiceObservation:
    panel_kind: str             # skill/bond/treasure
    panel_confidence: float     # 来自现有锚点，不来自 OCR 猜页
    frame_fingerprint: str
    slots: tuple[ChoiceSlot, ...]
    source: str                 # template/ocr/hybrid
    stable_frames: int
    reasons: tuple[str, ...]

ChoiceDecision:
    action: str                 # select/refresh/give_up/wait/close
    slot_index: int | None
    reason_code: str
    score_breakdown: dict
```

`ChoiceDecision` 不得携带屏幕绝对坐标。`Mediator` 只能把 `slot_index` 映射到同一帧、同一已确认面板的点击点。

## 7. B1：证据与遥测闭环

### B1-1 桌面版自动 trace

修改位置：`desktop_app.py` 的 `MediatorWorker.run()`。

任务：

- 创建 Mediator 后立即调用 `set_trace()`。
- trace 写到 `%LocalAppData%\GameScript-Local\YYYYMMDD\trace_*.jsonl`，不写安装目录。
- 正常结束和异常结束都关闭文件。
- trace 增加 `build_id`、设置摘要、窗口尺寸、帧指纹、页面、模板候选、OCR 建议、最终决策、动作结果和后置确认字段。
- 敏感设置（房间密码）不得写入 trace。

验收标准：

- 从桌面 EXE 启动 20 ticks 后必有合法 JSONL。
- 每行可独立 `json.loads()`；异常退出后最后已写入行不损坏。
- 密码、剪贴板和非目标窗口文字均不出现在日志。
- `ocr_mode=off` 下，新增 trace 不改变任何 action ledger。

### B1-2 未知页面/未知选择自动归档

任务：

- 在以下事件保存目标窗口全帧、相关 ROI 和 metadata：
  - `context=UNKNOWN` 连续达到 2 秒；
  - 选择面板分类失败；
  - 同一选择连续 2 次点击无页面变化；
  - OCR 与模板结果冲突；
  - LIVE 模式准备 Fail-Closed 前。
- 使用帧指纹去重，相同静态页面 60 秒最多保存一次。
- 每个 incident 包含上一帧、当前帧、下一帧（若能取得）、phase、HWND、尺寸、识别分数、候选动作和最终处理。
- 本地目录有容量上限；只删除本模块自己创建且超过保留期的 incident，不触碰官方日志和用户录像。

验收标准：

- 单元测试构造 10 个相同帧，只产生 1 组 incident。
- 不同页面各自留档，metadata 与图片可一一对应。
- 黑帧/错误窗口只记录健康错误，不被标成游戏未知页。
- 2 小时 shadow 运行后日志可持续写入，内存增长不超过 200MB，磁盘增长符合设置上限。

## 8. B2：OCR 离线评测，暂不接入运行时

### B2-1 数据集与标注

目录建议：

```text
fixtures/ocr_choices/
  manifest.json
  skill/<session_id>/...
  bond/<session_id>/...
  treasure/<session_id>/...
  negatives/<session_id>/...
```

每条标签至少包含：

- 原始全帧路径和裁剪路径；
- `panel_kind`、窗口尺寸、游戏版本、采集会话；
- 每个槽位的规范名称、原始可见文字、品质、套装进度；
- 是否可点击、预期点击槽位、禁止区域；
- 来源是实机截图、录像帧还是官方日志截图。

数据切分必须按“采集会话/录像”切，不得把同一视频相邻帧同时放入开发集和验收集。

进入生产候选前的数据门槛：

- 技能、羁绊、宝物各至少 30 个已标注面板；
- 每类至少包含 1600×900 与 960×540 两种尺寸，各不少于 10 个；
- 至少 20 个负样本：局内 HUD、暂停、商店、战后页、大厅、黑帧、聊天文本；
- 同一静态画面的连续帧只算一个样本。

不足时只允许继续 shadow 收集，不允许降低门槛直接上线。

### B2-2 OCR 候选和部署选择

首选评测百度/Paddle 的 PP-OCRv5 mobile 中文模型。首版采用固定文本 ROI 的识别模式；只有文字位置不稳定时才启用文本检测，避免每 tick 做完整检测。

OCR 试验使用独立 `.venv-ocr`，不得在现有 `.venv` 中直接安装或升级 numpy/OpenCV/Paddle。Agent 必须记录创建命令、Python 版本和完整依赖锁；删除 `.venv-ocr` 后，B0 基线仍应原样可运行。

Agent 必须在同一验收集比较：

- 原图 ROI；
- 2 倍放大 + 一种固定对比度增强；
- CPU 延迟、内存、模型大小；
- PyInstaller 冷启动和离线运行可行性。

只保留整体指标最好的一个生产实现，不写多 provider 抽象。

选择门禁：

- 规范名称 Top-1 准确率 ≥ 95%；
- 技能配置词典召回率 ≥ 99%；
- 非配置技能被归一化成配置技能的次数 = 0；
- 套装进度 `x/y` 完全正确率 ≥ 95%；
- 三槽识别 CPU P95 ≤ 300ms，单槽识别 P95 ≤ 120ms；
- 常驻增量内存 ≤ 800MB；
- 无网络时能完成加载和推理；
- 模型文件有来源、许可证、版本和 SHA256 记录。

如果达不到门槛，先修 ROI、词典和预处理；不得直接微调模型，也不得先加本地大模型补救。

### B2-3 词典归一化

`config/choice_lexicon.json` 仅保存事实数据：

- `canonical_name`；
- `aliases`；
- `kind`；
- `version_seen`；
- 明确观察到的 OCR 混淆写法；
- 可选套装归属。

归一化顺序：Unicode NFKC → 去装饰符/多余空白 → 精确别名 → 受限模糊匹配。

验收标准：

- 模糊匹配必须返回第一、第二候选与分差。
- 分差不足时返回 `None`，不能硬猜。
- 不同技能名称的混淆对必须有负测试。
- 词典未知项只记录原文，不自动写回生产词典。

## 9. B3：OCR 影子接入

### B3-1 设置与加载

只增加必要设置：

```text
ocr_mode = off | shadow | fallback
ocr_min_confidence
```

默认值在本阶段必须是 `shadow` 或 `off`，不得是 `fallback`。OCR 模型延迟初始化；未触发时不得加载模型。

验收标准：

- OCR 依赖未安装时，`off` 正常运行；`shadow` 明确记录不可用但不崩溃。
- 模型只初始化一次。
- 无选择面板的普通 tick 不调用 OCR。
- 静态同帧使用帧指纹缓存，不重复推理。

### B3-2 精确触发条件

影子 OCR 仅在以下条件之一运行：

1. `_selection_anchor()` 已确认中央选择面板；
2. `_panel_opened_by_us` 已确认 G/F/V 紧凑面板，且固定 ROI 可用；
3. 首选模板未命中；
4. 最佳模板与第二模板分差不足；
5. 同一动作连续两帧没有页面变化；
6. 已知页面分类冲突；
7. 当前 UI 指纹未在已验证版本矩阵中。

绝不因为“全屏 OCR 看到了技能/宝物两个字”而打开面板或点击。

验收标准：

- 全量场景回放中 shadow action ledger 与 B0 完全一致。
- 日志能同时展示模板结论、OCR 结论、冲突原因和最终仍采用的旧决策。
- 负样本 OCR 即使命中词典，也不能生成动作。
- 普通主线 tick P95 延迟相对 B0 增量 < 50ms；触发 OCR 的 tick P95 < 450ms。

## 10. B4：确定性选择策略

`src/gamescript/choice_policy.py` 必须是纯函数；输入结构化 observation/settings，输出 decision。不得读屏、计时、点击或保存文件。

### B4-1 技能规则

优先级：

1. 按 `settings.skills` 顺序查找已验证槽位；
2. OCR 兜底候选必须连续两帧名称和槽位一致；
3. 有配置技能则选择；
4. 没有配置技能且免费刷新未用完，则刷新；
5. 刷新次数用完则放弃；
6. 永不选择配置外技能，永不按颜色补选。

验收标准：

- 枚举“配置命中/不命中/空配置/同名低置信/两项相似/刷新 0..3 次/放弃按钮缺失”测试表。
- 配置外技能选择次数 = 0。
- 设置顺序优先于视觉分数和槽位左右顺序。
- 决策稳定：同样输入始终输出同样槽位和 reason code。

### B4-2 羁绊规则

优先级：

1. 用户明确预设；
2. 能立即完成或最接近完成的套装；
3. 用户流派偏好；
4. 品质：红 > 橙 > 紫 > 蓝 > 白；
5. 仍无法区分时选最左侧已验证槽位。

验收标准：

- “快要合成”必须由可见套装进度或已维护的局内羁绊状态支持，不能凭名称猜。
- 预设永远压过品质。
- 相同进度按品质、再按左到右稳定打破平局。
- 有至少一个已验证槽位时必须给出选择；无已验证槽位返回 `wait`，不能给坐标。

### B4-3 宝物规则

优先级：

1. 用户明确预设（如龙珠类目标）；
2. 套装完成度；
3. 用户策略偏好；
4. 品质：红 > 橙 > 紫 > 蓝 > 白；
5. 最左侧已验证槽位。

验收标准：

- 未识别到目标宝物时不能卡死，必须按降级规则选出已验证槽位。
- 龙珠模板误命中不得改变面板类型；面板类型仍由锚点/布局决定。
- 点击后 3 秒内必须看到面板关闭或内容变化；连续 2 次无变化则关闭面板并留 incident。

## 11. B5：技能 OCR 兜底上线

这是 OCR 第一个获得动作建议权的阶段；只开放技能，不同时开放羁绊和宝物。

运行规则：

```text
模板高置信命中配置技能 → 走当前路径
模板未命中/冲突 → OCR 两帧稳定 → choice_policy
OCR 命中配置技能 → Mediator 选择对应已验证槽位
OCR 未命中 → 当前刷新/放弃路径
```

验收阶梯：

1. 离线回放：所有技能正负样本通过，配置外误选 0。
2. Dry-run 实机：至少出现 20 个技能弹窗，OCR 建议与人工标签一致率 ≥ 99%。
3. LIVE 单局监督：至少完成 10 次技能决策，0 误选、0 连点。
4. LIVE 十局监督：配置四技能全部能学，配置外误选 0，技能弹窗卡住超过 10 秒次数 0。

任一阶梯失败，立即退回 `shadow`，不得继续 B6。

## 12. B6：羁绊与宝物 OCR 兜底上线

羁绊和宝物必须分两个提交、分两次验收；不得一次合并。

每类验收阶梯：

- 离线至少 30 面板，规范名准确率 ≥ 95%。
- 预设命中准确率 100%。
- 未命中预设时，降级规则在所有回放中都能选择已验证槽位。
- 20 次 LIVE 监督选择中错误槽位 0、无限等待 0、重复点击超过 2 次 0。
- 10 局监督运行中不会影响技能优先级和神器 120 秒调度。

特别禁止：

- OCR 把“刷新次数/暂时隐藏/放弃”文字当成卡名；
- 卡名 ROI 伸到聊天区或任务区；
- 用宝物固定第一槽作为无条件兜底；只有第一槽已被验证为真实卡槽时才可选。

## 13. B7：局外和固定页面 OCR 异常辅助

大厅、建房、房间、选关、开始关卡继续以现有模板/几何/时序为主。

OCR 只在以下异常时提供“页面辅助证据”：

- 模板分数处于灰区；
- 候选分差不足；
- 点击后连续 2 次无页面变化；
- 页面指纹发生版本变化；
- `context=UNKNOWN` 持续 2 秒。

危险按钮规则：退出、取消、确认、开始游戏不能仅凭 OCR 文字获得点击权。必须同时有：已知页面锚点 + 已知 ROI + OCR 文字/模板之一 + 后置状态机。

验收标准：

- 原有 L0 Replay 全部通过，禁止区域输入仍为 0。
- 至少为大厅、建房、房间、选关各准备 5 个正样本和 5 个相似负样本。
- OCR 不可用时，现有正常页面仍能按原路径运行。
- 对版本变更页只记录 incident，除非已新增回放并验收，不自动扩大点击区域。

## 14. B8：完整局内循环扩展

本阶段与 OCR 接入分离。只有 B5/B6 稳定后才做。每个小模块单独提交。

目标调度顺序：

```text
自动主线
→ 四挑战自动
→ 技能（优先，直到无可学点）
→ 羁绊
→ 宝物
→ 进化
→ 装备升级/属性三选一
→ 英雄升级/英雄卡
→ 黑商
→ 背包消耗品
→ 回到技能

神器：独立周期任务，每 120 秒最多触发一个槽位，仍遵守每 tick 一个输入。
```

### B8-1 调度器

任务：

- 不引入任务框架；在现有 MAIN_LINE 中维护一个简单的下一动作游标和冷却时间。
- 高优先级弹窗、失败/断线、暂停、战后页面随时抢占普通循环。
- 每个子动作返回 `Continue/NoWork/Wait/Blocked` 等有限结果，由 Mediator 决定下一项。

验收标准：

- 每 tick 输入数 ≤ 1。
- 连续 3 轮某模块 `NoWork` 后仍能转到下一模块。
- 某模块 `Wait` 不得永久饿死技能；有明确超时和 incident。
- 神器到期不会被持续出现的进化按钮永久饿死。

### B8-2 装备升级与属性三选一

规则：装备栏第 1 格右键一键升满；每 10 级属性三选一按红 > 橙 > 紫 > 蓝 > 白；没有属性弹窗则进入下一动作。

验收标准：

- 必须先有装备槽位锚点，禁止裸固定坐标右键。
- 右键后用装备等级/弹窗出现/按钮状态之一确认变化。
- 属性弹窗至少连续两帧确认，品质颜色规则有正负样本。
- 无弹窗时零点击进入下一动作，不等待超过 3 秒。

### B8-3 进化、英雄升级与英雄卡

规则：英雄卡使用前检查“进化”按钮；按钮亮则先点击进化，再在后续帧确认后使用英雄卡。

验收标准：

- “亮/不亮”有独立 ROI 和阈值测试，不凭整屏亮度。
- 同一帧不能既点进化又点英雄卡。
- 点击进化后必须确认状态变化；失败最多重试 2 次。
- 背包不是英雄卡时不能误点。

### B8-4 黑商

规则候选：优先吞噬丹，其次木头；折扣文字由定点 OCR 读取，只有满足已确认规则（例如 5 折及以下）才购买其他目标物品。

验收标准：

- 商品图标、价格/折扣、购买按钮必须属于同一商品槽位。
- 折扣 OCR 低置信或价格 ROI 缺失时不购买。
- 非目标商品、原价商品、相邻商品按钮是必测负样本。
- 一次刷新/购买后必须用商品变化或资源变化确认。

### B8-5 吞噬丹与背包消耗品

规则：羁绊栏非空才允许使用吞噬丹；英雄卡遵守 B8-3 的进化前置条件。

验收标准：

- 羁绊栏为空的所有回放中吞噬丹点击数 = 0。
- 羁绊栏识别 UNKNOWN 时按空处理。
- 图标与槽位必须同时确认；相似紫色/金色物品不得误用。
- 使用后确认物品数量或槽位内容变化。

### B8-6 神器周期

沿用当前 `_maybe_fire_artifacts()`，不重写。

验收标准：

- 以 `_main_line_started_at` 为计时基准。
- 前 30 秒不释放；每槽按设置冷却。
- 空槽跳过；每 tick 最多一个 Q/W/E。
- 新一局重置计时；长时间运行无漂移导致的连发。

## 15. B9：偏好观察与轻量学习

首版不微调本地模型。先做用户显式同意的目标窗口观察：

- 只记录游戏窗口内、已知选择面板上的用户点击；
- 保存当时三个结构化候选、被选槽位、设置和结果；
- 不记录全局键盘输入、非游戏窗口、聊天正文；
- 原始图片有保留期，长期只保存结构化选择事件。

第一版偏好学习只使用计数/成对排序：

- 某流派下 A 对 B 的选择次数；
- 稳健/赌性偏好；
- 自身属性、套装完成度和品质权重；
- 用户可查看、重置和关闭。

验收标准：

- 关闭观察后不新增任何偏好事件。
- 相同上下文的留出集上，简单偏好排序命中率 ≥ 80% 才允许作为羁绊/宝物的末级加分。
- 学习结果永远不能越过技能白名单、吞噬丹前置条件和危险按钮安全条件。
- 偏好数据损坏时回退静态规则，不影响启动。

只有同时满足以下条件才评估本地小模型：

- 已有 ≥ 1000 个独立人工选择事件，覆盖 ≥ 100 局；
- 静态规则与用户选择冲突率仍 > 10%；
- 模型在按会话隔离的留出集上比简单排序提升 ≥ 5 个百分点；
- CPU P95 推理 < 100ms；
- 模型只输出候选排序，无直接点击权。

否则不训练、不微调。

## 16. B10：打包、发布和长期稳定验收

### B10-1 OCR 打包决策门禁

离线评测后再二选一：

- 若单进程 PyInstaller 增量体积 ≤ 350MB、冷启动 ≤ 8 秒、干净机器稳定，则直接随主程序打包；
- 否则将 OCR 做成同目录的本地 sidecar，使用 JSONL stdin/stdout，只处理裁剪 ROI，不接触输入。

不提前同时实现两条路径。

验收标准：

- 干净 Windows 机器无 Python、无网络也能启动和识别。
- 模型路径兼容源码运行和 PyInstaller `_MEIPASS`/onedir。
- `ocr_mode=off` 不加载 OCR DLL/模型。
- 模型缺失或加载失败有清晰日志，主程序不崩溃。
- 发布目录内包含版本、模型哈希、构建 commit 和回滚说明。

### B10-2 分级实机门禁

| 级别 | 运行规模 | 通过条件 |
|---|---:|---|
| S0 | 全量离线回放 | 单测全绿；Replay Failed=0；禁止输入=0 |
| S1 | Dry-run 2 小时 | 无崩溃；incident/trace 完整；无动作权泄漏 |
| S2 | 1 局人工盯跑 | 主线/四挑战/选择/退出完整闭环，误点=0 |
| S3 | 10 局人工监督 | 配置外技能=0；卡死>15秒=0；错误页面输入=0 |
| S4 | 30 局或 4 小时 | 自动恢复率≥95%；进程无明显内存持续增长 |
| S5 | 累计100局且12小时 | 至少一次连续6小时；0误技能、0禁点、0崩溃 |

S5 资源门槛：

- 非 OCR tick P95 ≤ 500ms；OCR tick P95 ≤ 800ms；
- OCR 触发率应是异常/弹窗级，不得在普通 HUD 每 tick 运行；
- 运行 6 小时 RSS 增长 ≤ 300MB；
- incident 目录受容量上限控制；
- 最小化、遮挡、窗口切换、断线、暂停时不盲点；
- 任意不可恢复事故都能由 trace + 3 帧证据在离线回放复现。

只有 S5 通过，才可对外称为“长期稳定、多局无人值守”。

## 17. 每个 Coding Agent 的统一交付格式

每个 Agent 一次只接一个 `B?-?` 小任务，并回传：

1. 基线 commit 与自己的 commit hash；
2. 修改文件清单；
3. 为什么必须修改这些文件；
4. 新增依赖、模型、许可证与体积（没有则写无）；
5. 单元测试、Replay、compileall、`git diff --check` 原始输出和退出码；
6. action ledger 与 B0 是否一致；若不一致逐条解释；
7. 新增 fixture 来源及人工标签；
8. 性能 P50/P95、内存和测试机器；
9. 哪些条件仍未实机验证；
10. 回滚方式。

Agent 禁止：

- 合并多个阶段制造大提交；
- 删除/放宽旧测试来通过；
- 修改 `dist_release2`；
- 重写整个 `Mediator`；
- 让 OCR 或策略模块直接调用鼠标键盘；
- 在没有真实证据时新增固定坐标；
- 自动把未知 OCR 文字写入生产词典；
- 用“日志看起来正常”替代回放和后置确认。

## 18. 项目负责人验收清单

我对每个提交按以下顺序给出“通过 / 有条件通过 / 退回”：

1. 审查 commit 范围、dirty worktree 和用户文件保护。
2. 检查是否保持 15 条安全不变量。
3. 检查新增依赖是否必要，是否有模型来源和许可证。
4. 运行 compileall、全量 unittest、scene 校验和根 Replay。
5. 运行新增 OCR 离线评测，并抽查错例而非只看平均数。
6. 对比 action ledger，确认 shadow 没有获得动作权。
7. 检查技能白名单、UNKNOWN、低分差、错误页面、错误 HWND 等负路径。
8. 检查每个动作的前置证据、一个 tick 一个输入、后置确认和有界恢复。
9. 检查 EXE 离线启动、模型加载、日志路径、体积和回滚。
10. 只有当前门禁全部通过才允许派发下一阶段。
