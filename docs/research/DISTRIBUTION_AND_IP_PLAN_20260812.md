# 分发、订阅与核心链路防泄露（2026-08-12）

## 1. 产品分层（已拍板）

| 层 | 内容 | 订阅 |
|---|---|---|
| 本地习惯权重 | 用户操作 → 本机 preference；只调「允许集合」内优先级 | **免订阅** |
| 官方权重包 | 测试后的 presets / 负面名单 / quality_order；打进发布包或签名 JSON | **要**（与 LIVE 正版一起） |
| 核心自动化链路 | 截图→匹配/OCR→状态机→InputExecutor | **要**（真正护的对象） |
| 许可服务 | 是否有效、到期日、租约签发 | 家庭电脑起步 → VPS |

不做：云端逐 tick 选卡、上传对局截图换策略。

```text
用户本机：识别 + 执行 + 习惯权重
官方包：presets / 规则（可签名，不幻想保密）
许可：启动/心跳问「能否 LIVE」；断网仅短宽限期
```

## 2. 断网与破解现实

- **会**：改 EXE、永久缓存「已授权」、断网放行、拷贝正版包给他人。  
- **本地学习不会单独造成越权**；危险的是「校验失败仍 LIVE」。  
- 对策：有期限租约 + 机器码绑定 + 断网不永久放行 + 到期用 NTP/服务端时间。

## 3. 参考项目（`参考/1.3.3.3`）怎么做

```text
DeviceId 机器码
  → Standard.Licensing 证书 (LicenseTxt)
  → CertClient + SignalR Hub 在线事件
  → NetworkTimeHelper NTP 防改时
  → Costura 单文件 + ConfuserEx 混淆 + 部分程序集加密
```

仍可被运行时 dump；目标是提高抄袭成本，不是数学不可破。

## 4. 我们能否加密核心、能否更好

当前 Python + PyInstaller **弱于**参考项目静态门槛。

| 阶段 | 动作 | 相对参考 |
|---|---|---|
| A 现在 | PyInstaller 自用/内测；不发源码仓给客户 | 弱 |
| B 收费起步 | 家庭电脑许可 API；租约+宽限期；官方权重签名 | 授权接近，代码仍弱 |
| C 对齐 | **Nuitka（或 Cython）编译** `mediator`/input/`choice_policy` 热路径；发布无 `.py` | 静态可接近 |
| D 可选更强 | 热路径进 Rust/C++ DLL；强更+吊销 | 关键逻辑可更难读 |

原则：

1. 习惯权重：本地明文即可。  
2. 官方权重：签名防篡改，不当永久秘密。  
3. 护核心链路实现，不护「用户自己的偏好文件」。  
4. 私钥（支付/吊销）永不进客户端。

## 5. 许可服务部署节奏

| 阶段 | 部署 | 触发 |
|---|---|---|
| 0 | 本机开发机跑许可 API | 内测 |
| 1 | 现有 RackNerd 或任意 VPS | 付费用户变多 / 家用机不稳 |
| 2 | 国内 2核2G～4G | 国内启动校验常超时 |

客户端只依赖稳定 HTTPS 契约；搬家只改 base URL。

## 6. 与「刷刷宝」发布物关系

- 开发仓：继续可测、可门禁。  
- 客户包：编译热路径后的 onedir/onefile + OCR sidecar + 官方权重；**不含** `.git`、测试夹具真值全集、研究文档非必需部分。  
- 订阅校验失败 → 拒绝 LIVE（零输入）；可选开放「仅本地学习/ dry-run」需产品明确开关，避免误送核心。
