## 2. 优化目标

优先保证可控运行和有效推进，在此约束下提高本局目标收益。关注的是“资源何时转成有用的战力、成长和通关进展”，不是点击数、花光木材或清空技能角标。

技能点不丢失、不设上限，说明没有单纯的囤积损失；但如果学习后能提高当前击杀和主线速度，推迟学习仍可能有战斗机会成本。该成本应由已确认技能效果和战斗反馈支持，不能仅从积压数推断。羁绊也不是永远第一：成长卡、启动卡通常有时间价值，短期无法成型的长链与立即解锁主线的技能需要具体比较。

## 3. 单一决策入口，复用原执行器

观察当前状态 → 生成合法候选 → 比较当前机会 → 执行一个动作 → 原 FSM 确认后置 → 更新事实 → 再比较。

调度器只回答“做什么、为什么、依据是什么”，不自己识图、点击、复制业务 FSM。不从旧 runtime_core 分支整套搬入第二个运行时；先复用当前 mediator 的识别、动作保护和事务。

统一入口仅在稳定可交互面、无未完成事务时选择下一动作。自然奖励弹窗、进化英雄选择、装备词缀、购买反馈等正在进行的事务按原流程收完。每 tick 最多一个改变 UI 的动作。一次成功后重新观察，允许新机会改变下一步；不因为微小读数变化在 F/G/V 之间来回开关。

首版优先落成纯决策函数及小型候选记录，避免引入插件系统、通用规划框架、学习型执行器。旧轮换在信息不足时只作为已授权安全候选的次序参考，不能绕开合法性检查。

每项观测携带 value、source、frame/事件、observed_at、round_id、有效性。未知与 0 分开；影响支付/目标身份的旧值不得作为当前动作授权。

## 5. 如何决定下一步

首版采用可解释的比较规则，不把一组任意权重包装成动态评分。

1. 排除不合法候选：目标/页面不可信、配置未启用、未知支付能力、负面禁拿、前置未满足、事务占用。
2. 处理已确认的紧迫问题：生存危险、真实失败后的战力缺口、有证据的时效机会。仅“同关很久”需要进一步判断，不能自动等于缺技能。
3. 看是否存在短链收益：已展示且差一张成型的有效羁绊、已就绪且效果已知的进化、能直接补当前短板的技能，优于盲目寻找未出现的远期收益；仍受安全/白名单和实际成本约束。
4. 比较延迟损失与成本：成长启动的延迟、主线堵塞的损失、操作及打开面板的成本、资源预算、占用卡位、能否在下一相关战斗前兑现。
5. 无明显优势时，保持当前有效发育链的连续性；等价机会按等待时间公平服务。等待加权只影响已合法候选，不把低价值/不安全动作提升为必做。

未知收益不填零、不虚构抽卡概率。可用“确定当前收益 / 有机制支持的远期收益 / 仅推断”分级；无法比较时选择已知可推进且切换成本低的候选，或安排一次有决策价值的观察。

## 6. 主支线怎样穿插

| 动作 | 应提高优先级的证据 | 让位或停止的情况 |
|---|---|---|
| 羁绊 | 已授权成长/启动机会；差一张兑现；符合英雄和现有链；投入能在相关战斗前生效 | 当前页无合法候选；资源不足；长链短期无法兑现且已有直接战力方案 |
| 技能 | 可学习且匹配所选技能；当前输出/生存短板与效果相关；羁绊暂不可推进 | 不能仅因积压 >=N 抢占；零勾选不打开；无合法技能不反复空开 |
| 宝物 | 有真实待领取次数；当前页已有安全有效选项；能解锁/加强当局构筑 | 先滤负面；未知效果不因为免费就随便拿；无次数不空开 |
| 点击进化 | 真实入口、未处理的新机会、效果/选择可确认；能产生明显发育跃迁 | 事务中禁止切走；同按钮持续出现不算新机会；失败后按反馈退避 |
| 武器/物品栏 | 升级确能补短板；英雄卡可用；清理空间能解除下一步阻塞 | 保留进化/词缀先后约束；受保护卡未知时不得随机吃丹；满仓不盲目拾取 |
| 神器 | 有实际战斗需求且效果、可用性可确认；延迟会损失一个有效释放窗口 | 配置 CD 到期只是可检查条件；不能把发出点击记成战斗收益 |
| 黑商 | 可见合法商品直接解除缺资源/缺刷新/缺空位等瓶颈，且能支付 | 不为“轮到了”付费刷新；刷新预算必须覆盖后续购买；无反馈则退避 |
| TAB 观察 | 当前候选的优劣会因某个未知属性而改变；进化/成型后旧属性已过时 | 正在战斗应急/处理弹窗时不打开；观察不影响决定时省略 |

一个有价值的支线可以早于主线拿卡：例如武器升级能解除输出不足；宝物领取能给当前技能增益；黑商的已验证木材商品能使关键合成可支付。它们服务本局目标，不固定等到 F/G 全部做完。

## 7. TAB 与英雄属性

这里暂按 Owner 的 tap 指游戏内 TAB 详情属性；若指别的看板需重新对应入口。

分两份数据：entry_profile 是开局存档底子；run_attributes 是本局实时快照，带时间、英雄形态和上下文。实时变化只更新本局状态，不污染玩家长期画像。

复用 parse_attr_panel 的解析能力前要审计其契约：目前负值、超硬顶会被拒绝。这对画像的异常过滤未必适合本局带 debuff 或上限变化的属性，不得把合法的极端值改成 0。先保存原文与 rejected 原因，再由字段机制判断，不直接放宽全局解析边界。

属性用于匹配作用方向和避免无效增益，不用于臆造精确伤害公式。现有 KB 的敏捷/智力伤害递减公式未知；高攻击力不等于高 DPS。英雄的已选技能、伤害类型、攻速/暴击/急速、已生效羁绊需联合判断，不能凭最高一项属性自动换流派。

TAB 采样触发点优先为：开局可观察窗口、英雄进化或关键成型后、真实主线失败且需要属性解释时。每次开关面板需有确认；同一次决策缓存复用结果。没采到 TAB 时继续运行已知合法策略，不把全局调度阻塞在新观测上。

## 8. 资源转化与动态预算

预算围绕当前有证据的目标形成：下一次明确购买、关键合成所需投入、已确认的刷新后购买组合；目标失效后释放预留。不要统一设置木材必须留 300/500/1000。

候选收益只能预测短距离、可解释的后续动作。黑商“刷新→买到目标”带随机性，未见商品前不得当确定收益。手上已展示的合成卡和未知下一抽区分。木材增长率只从本局可解释区间估计，领取奖励、买卖/转换、同帧多事件单列，不把余额差直接当总收入。

至少记录以下指标：

- 花费中有确认获得的比例，及获得是否推进目标链；
- 已可支付且存在有用机会却未处理的等待时间；
- 合成/进化确认次数，关键主线推进和失败次数；
- 无效刷新、空开、重复无反馈、面板切换耗时；
- 木材/杀敌/金币分别的账目覆盖率与不明变动；
- 技能/宝物等合法机会最长等待时间。

支出÷收入仅在账目完整且口径明确时报告；存在开局存量时不能把它直接叫效率，也不能以比值更高判策略更好。更换策略后的通关变化受英雄、装备、难度和随机掉落影响；离线重放只能验证决策一致性，不能证明收益提升。

## 9. 验收场景

以下是离线策略场景，合成输入不代表实机证据：

1. 木材不足旧 300 阈值，但当前展示的合法关键卡可支付，应参与比较，不能直接禁 F。
2. 技能点积压很多、战局稳定且有成长启动机会，不因积压数强抢占。
3. 同样技能点与木材，出现真实挑战失败且有可确认的有效技能升级时，下一动作可以改变。
4. 有待领取宝物且能补当前构筑，不能因持续有木材把 V 永久饿死。
5. 进化进入待确认状态，新技能/神器机会不得打断；确认后重新评价。
6. 黑商刷新可支付但无法覆盖后续购买时，不烧掉最后的购买资源。
7. 可见吞噬丹但保护卡身份不明，不解除现有禁止消费保护。
8. TAB 缺失、旧读数或跨局，不授权依赖该属性的操作；仍能做独立且可信的动作。
9. 相同余额、不同实际卡链进度/英雄配置，决策可不同；均不越白名单。
10. 新模型无信息优势时，保持稳定和可解释；不为“动态”制造面板抖动。

## 10. 实施与交付边界

A. 外部证据 agent 核对已有信号、TAB 原帧、动作效果、价格及 TASK_H 基线，提交紧凑矩阵；不代替主架构选策略。
B. 主架构据证据确定候选结构、比较顺序、降级与边界场景，再给唯一 L1 实施 agent 精确代码任务。
C. 第一实施阶段只记录动态候选和推荐动作，不改变执行；记录与真实帧/动作逐条对齐。复用可用的现有观测设施，避免复制一个业务运行时。
D. 同一 L1 agent 串行接入：先主线拿卡竞争，再逐个接入已验证支线；每阶段单独提交、回归与 C2。新增状态同步重置/污染清单。
E. 主架构合并、身份提交、独占完整门禁；Owner 开实机后做同难度/配置分层的短局验收，再扩大。打包 9ed8b52 继续独立收口，不混入未验收策略。

安全重试、事务超时、OCR 频率和 CPU 预算仍需有界；取消的是缺乏机制依据的固定策略门槛，不是取消保护上限。

## 11. 主架构收口：可实现的决策契约（本轮新增）

本节是首版离线决策契约，不授予真实输入。外部实施必须保持旧执行路径不变，先用真实观测验证推荐解释。语义由主架构负责，未知项不由执行 agent 自选权重补齐。

### 11.1 三类事实不能混用

- observed：画面/事件明确看到的机会或结果，带本局、页面及证据引用。
- requested：已经发送动作，即便 ok=true 也不等于效果生效。
- confirmed：原执行器的业务后置已确认。只有它能推进持有卡/已购/已进化等账目。

本次 Boss 审核就是反例：click:17年兽 ok=true 但 post_confirm 为空，只能说目标点击被接受。动态调度不能以 requested 更新战力、消耗收益或完成目标。

### 11.2 输入、输出与候选

输入：只读本局观测快照、正在进行的事务、Owner 配置约束、最近一次 confirmed 动作结果。各字段区分 unknown/missing/invalid/observed，不使用 0 冒充未知。

候选最少包含：action_id、目标/页面、合法性与拒绝原因、依赖的事实引用、各币种成本、预期兑现点、所解决的瓶颈、收益依据、执行器名称、确认条件引用。这些是决策资料，不构建第二套视觉识别或输入实现。

输出三种：

1. CONTINUE_TRANSACTION：返回当前事务，由原 FSM 继续观察/完成，不安排第二项业务动作。
2. RECOMMEND：给一个合法动作及支持证据、未选替代项与原因；影子阶段仅记录，不执行。
3. WAIT_OR_OBSERVE：没有可推荐动作时，明确缺失事实与可用的既有观察入口；不存在安全观察入口则等待。

禁止由调度函数读取磁盘/网络、发 OCR、读取隐式当前时间或发输入。时间从快照传入。相同快照应产生相同结果。

### 11.3 决策顺序

A. 当前事务和强恢复先由原运行时接管。只有无事务且已授权的交互面才进入候选比较。
B. 合法性先筛选。消费类余额/价格不可信时不授权该消费；保留其他不依赖该未知字段的机会。
C. 先比较候选是否有证据解除当前紧迫阻塞。挑战失败只证明需要检查战力，不能自行区分输出/生存；无对应效果依据时不把某技能封成唯一解。
D. 对剩余候选做支配比较：若 A 能服务相同目标、收益证据不弱、各币种成本与切换成本均不更差、兑现不更晚，且至少一项明确更好，则 B 不优先。未知维度不能视作更好；不同币种不可擅自换算。
E. 无可证明支配时：有确认时间价值的机会优先于仅推断收益；仍不可比则在已验证的目标偏好内保持当前有效链，未服务的等价机会依次获得服务。候选类型名称本身不赋“羁绊永远大于技能”等绝对排序。
F. 缺某观测会改变选择且已有安全读取入口时，再读该信息；否则选择不依赖缺失信息的候选或 WAIT。首版无法比较的高影响分歧记 REVIEW_REQUIRED，影子运行不改变旧执行。

这是保守的部分排序，不要求编造 DPS、成卡概率或统一金钱收益评分。首版的不可比率本身是要测量的指标，不以强行选一个掩盖机制缺口。

### 11.4 动态预算与信息成本

预算只绑定已选择且可解释的短期目标。已展示的商品/卡片可报价；未知下一次刷新只算随机机会，不能记成保证收益。预留额度、币种、目标与取消条件一起记录；目标消失、前置失败或已完成立即释放。

F 的某些操作会直接付费抽卡，不能把它当无成本“看看面板”。候选必须区分 READ_EXISTING_PANEL、PAID_DRAW、PAID_REFRESH；V 是否耗领取次数也独立记账。UNKNOWN_PRICE 不填 0。使用缓存的代码价须标 model-derived，不冒充实价。

信息的有效期优先按事件失效：花费后余额需重读，选择后持有/角标需确认，进化后英雄属性失效，换页后目标位置失效，换局后本局状态全部失效。时间限额只是兜底；旧画面不能因尚未超过秒数就继续授权坐标。

### 11.5 让位与防饿死

只在事务完成或已安全退出的边界重评，不逐 tick 把已打开面板关掉重开。一个候选的“服务”是得到确认结果、明确无合法选项或明确失败，不是成功发了一次点击。

当收益不可比较且不存在更紧迫有证据的机会时，已等待的等价候选获得下一次服务；服务后重评。不用“每隔 N 秒必须点一次”制造空操作。持续无反馈的相同机会不刷新有效进展时钟，由原重试/退避保护收敛。

### 11.6 首批确定性验收矩阵

| 场景 | 首版预期 | 禁止结果 |
|---|---|---|
| 进化待确认，技能角标很大 | CONTINUE_TRANSACTION | 另开 G |
| 只有技能积压数增加，其他事实相同 | 不因此产生紧迫战力标签 | 用 >=8 恢复硬抢占 |
| 真实挑战失败，但效果/短板均未知 | 观察或标不可比 | 声称学技能一定解墙 |
| 关键合法卡已展示且可支付，木材低于 300 | 卡进入合法候选 | 仅余额档位排除 |
| 同目标两动作，A 各成本不高、兑现更早且有证据 | A 支配 B | 仍按固定轮换选 B |
| 一项耗金币、一项耗杀敌，收益缺可比依据 | 保留不可比 | 任意汇率换算总分 |
| 刷新花费可支付但购买目标预算不足 | 不推荐该刷新购买链 | 刷光资源 |
| 宝物与当前链等价且长期未获服务，事务已结束 | 给宝物一次服务机会 | 永久留在 F |
| 选择卡 ok=true，结果未确认 | 持有账目不增加 | 推进合成进度 |
| TAB mid_run 与 entry 不同 | 仅更新本局快照 | 覆盖开局画像 |
| 丹可见但保护卡信息不全/原守卫关闭 | 排除消费 | 用满仓理由绕过守卫 |
| 跨局/跨页面旧坐标或余额 | 依赖项失效 | 沿用旧值授权动作 |

验证要求：这些场景只验证策略语义；真实接口映射和原帧回归另验。可推荐率、不可比率、未知阻塞率、与旧执行分歧原因都必须报告，不能把“影子有输出”作为策略有效证明。
