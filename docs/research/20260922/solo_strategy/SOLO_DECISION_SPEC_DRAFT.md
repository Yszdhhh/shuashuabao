### 3.3 脚本3「正向停止 + 冷却」FSM —— 利弊分析

**FSM 摘要**（脚本3，1366×768 基准）：

- 正向停止：同一商品同位 **3 连点仍在** → 判资源不足，停。
- 冷却非判死：H 刷新前后像素 **2 次无变化** → 10s 冷却后可再试。
- 采样故障返回 999 = 永远算「有变化」，防误判停死。
- ONE ACTION THEN RESCAN：黑市预购一步后强制回顶重评。

| 利 | 弊 |
|---|---|
| **高**：补我方 merchant 缺「正向停止」——避免无限点同一格（资源不足时） | 坐标/像素阈值是 **1366×768** 基准，须我方 1600×900 重标定 |
| **高**：冷却非判死，比 fail-open/永久停更稳；与我方 fail-closed 哲学兼容（停输入 ≠ 停进程） | 「3 连点仍在」依赖像素稳定性；特效/遮挡易误判 → 需指纹双证据 |
| **高**：与我方 merchant ≤20 reroll 对比，可收束为「有界 + 冷却」 | 引入新 FSM 状态须过 C2（局内状态污染清单 `INGAME_POLLUTION`） |
| **中**：与脚本3「5 次放弃→5s 冷却但不刷活性时钟」同构，可顺带修我方 R1（panel 检疫饿死 idle watchdog） | 改动属 L1 层，须单独 commit + 冻结回放 + 任务 H 基线 |

**拟议结论**：**有条件借鉴**（采纳语义，拒绝坐标）。落地前置：真机 GT 标定 ROI/阈值 + TASK_H 基线 + Owner 拍板（D9）。
