## 3. 有价值的机制骨架（可收编）

```text
宝物 taxomony（analysis_only）
├─ A 赌运/随机：梭哈族（金/木/杀）、命运骰子、混乱洗牌、混乱转换
├─ B 代价/负面：诅咒之力、恶魔契约(待证卡名)、力之极、生命献祭、超级水桶腰、
│                透支力量、金转木、伐木契约、提高上限(实为负面)、压制、玻璃大炮…
└─ C 上限/成长：混乱重置、混乱分配、传说宝藏、声名鹊起（多未 live）
```

横切事实（以 live 优先）：
1. **梭哈失败 ≠ 空过**，木材/杀敌梭哈失败是 **清零**。  
2. **诅咒之力** = 高输出 + 恢复-99% + 护甲-10000，不是简单禁疗。  
3. **「提高上限」在我方 live 是负面**，勿与外部「上限提升类」混名。  
4. **等级优势 ≠ 恶魔契约**；锁 25 级若存在是**另一张卡**。  
5. 混乱转换 × 上限类 双触发是 **combo 假说**，无 live 概率。

## 4. 对「海贼王适配」专段的处理

- 外部：「必拿木材梭哈/混乱转换…绝对避坑恶魔契约/力之极」。  
- **问题**：①海贼王机制本身未进 live 策略；②「必拿/绝对」与 Owner「默认可跳过特殊宝物」冲突；③木材梭哈在我方是 **default skip**。  
- **裁决**：仅作 `guide` 意见存档；**不写 choice_policy / dashboard 默认**。实机若验证海贼王吃全属性，再单独开实验档。
