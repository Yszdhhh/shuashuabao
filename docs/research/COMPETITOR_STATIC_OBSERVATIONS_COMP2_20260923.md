## 一、 PE 物理结构与载荷挂载逆向

通过对二进制结构的深度剖析，竞品2的打包体系在商业化防逆向领域具有极高的工程研究价值：

```
0x000000 ┌──────────────────────────────────────────────┐
         │ PE Header + Sections (Text, Rdata, Data...)  │
         │ VMP / 高混淆代码段 (节名 zmtibtux, 熵值 7.988) │
0x329200 ├──────────────────────────────────────────────┤
         │ Authenticode 数字证书区 (13,488 字节)          │
         │ 附带微软驱动签名信息 (用于对抗部分 EDR/AV 扫描)  │
0x32C6B0 ├──────────────────────────────────────────────┤
         │ 附加载荷区 (Overlay Data, 13,324,486 字节)   │
         │ 固定 1-Byte XOR (0xCC) 混淆流                  │
         │   - Item 0: uservar_config.ini (配置表)      │
         │   - Item 1~6: package_1..6_qmcfile.zip       │
         │               (6 个分卷加密 QMC 脚本归档)    │
0xFE0C66 └──────────────────────────────────────────────┘
```

## 二、 对 ShuaBao 商业化打包的技术借鉴与裁决

| 竞品2 技术特征 | 攻防机制原理 | 刷刷宝裁决 (ADAPT / REJECT) |
| :--- | :--- | :--- |
| **Loader 与内核彻底分离** | 主 EXE（3.3MB）仅负责提权与环境初始化，核心资产以加密流动态载入内存 | **ADAPT (中长期)**：彻底消除明文 Python 裸露，采用编译型 Loader 加载加密代码包 |
| **资产 Vault 保护** | 磁盘不释放任何明文 `.png` / `.bmp` 模板，内存直接 `imdecode` 解码 | **ADAPT (P1/P2)**：杜绝我方 `assets/Images/` 明文图片在磁盘裸奔，收束为加密 Vault |
| **分卷模块独立热更** | 修复特定玩法只需替换对应 Zip 分卷，无需重编主程序 | **REF**：微内核模块化思路，便于按需更新 |
| **按键精灵绝对坐标** | 依赖 1920x1080 绝对屏幕像素点击，无页面身份严格二次校验 | **STRICT REJECT**：极度脆弱，多屏/缩放即崩溃 |
| **签名遮蔽免杀 (Cloaking)**| 利用 PE 证书末尾挂马绕过检测 | **STRICT REJECT (红线)**：合规与商誉风险，我方坚守正规代码签名证书 |
