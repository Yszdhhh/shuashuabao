## 结论先行

1. Q1 七组的“终点身份”比“完整配方”可靠得多。[live] 最终规范名可钉为：刀刀→解放的圣剑 EX、修仙→大乘期 EX、海盗→毁灭战舰 UR（无 EX）、亡灵→兵主 EX、大圣→法天象地 EX（卡面 family 可写“神通”）、异火→帝炎 EX、封神→圣人 EX。修仙逐阶 recipe、海盗终点触发、封神榜吞噬周期等仍有 none / guide conflict，详见 synthesis_chains.json。
2. Q2 是当前最大 P0 风险。[none] 目前没有 retained 实机证据证明普通吞噬丹究竟“随机吞 / 最早 / 最低品质 / 允许点选目标”。公开攻略大量用“用丹吞掉某张指定卡”的操作语言 [guide]，同时反复警告封神、海盗等在错误时机吞会损失进度 [guide]。因此 Owner 的“≥6/10 就吃丹”若直接理解成“只看占用数就点击丹”，存在吞错承重卡的真实风险；更安全的设计解释应是“≥6/10 触发吞丹检查/排程，而不是单独授权消费” [inferred]。
3. Q3 黑商能确认“5 槽 + H + 180 秒 1 次免费刷新 + 2/5/8 折” [live]，但不能确认吞噬丹固定 400、付费刷新固定 350。最新机制 KB 和 PR #41 已把这两个价格列为未验证；旧 runtime handoff 里的 400/350 只能视为旧实现预算，不是游戏机制证据。
4. Q4 不存在一条可复用的“第 N 分钟 = 500/1000 木”时间线。[none] 木材高度受初始奖励、主线、经济羁绊、宝石、梭哈与 F 消费影响。公开攻略能给出部分增量率，如成长约 +0.2 木/秒、经济-挑战约 +0.4 木/秒 [guide]，但不能把它们当成基础收入曲线。500/1000 的分钟映射必须从本机 trace 对齐。
5. Q5 物品栏是 6 格 [live]：1 号武器位 + 2–6 五个可移动道具格；背包页面个人网格是 7×8 = 56 个“可见几何格” [live]，但实际解锁可用格数未钉 [none]。满栏后新道具究竟掉地/进背包/拒绝拾取 [none]；个人背包↔物品栏的可靠移动手势也 [none]。
6. Q6 “贪婪”不适合放进无条件基础优先链。它 need=3，效果是随机吞 4 张可吞卡 +150 木 +888 杀敌 +6000 金 [live]；攻略既有“利用贪婪清掉海盗/亡灵房子”也有“有贪婪都别点”的强时机依赖 [guide]。建议把它定义为条件型卡槽/经济工具，位于 Owner 固定基础序列之外，仅在“当前随机吞 4 张的候选集合都可接受”时升权 [inferred]。

## 对“≥6/10 就自动吃”的风险裁定

[inferred] ≥6/10 只适合成为“吞丹排程触发线”，不适合单独成为“点击授权线”。

原因：

1. [live] 当前自动化历史上就曾因为“没有可靠 per-slot identity”把吞丹 fail-closed；后来的 8/10 使用路径只验证栏位数量下降，并不验证到底吞了谁。
2. [guide] 高级卡大量是“先占格→等时间/击杀/吞噬→再进阶”，一个 6/10 栏里完全可能同时有封神榜、修仙山、大圣材料、近合成基础卡。随机/错误目标的代价不是少一张普通卡，而是把整组兑现时间打断。
3. [live] Owner 规则锁已经把“差一张合成”作为高价值容量状态；这类卡更不能因为栏位超过一半就被清。

### 建议的安全条件（研究结论，不是生产默认值）

[inferred] 自动普通吞噬丹至少需要满足：

- 当前是单人模式且 Owner 明确开启自动丹；
- 占用 ≥6/10 只负责触发检查；
- 能明确识别一个目标槽位，且目标满足：
  - 不属于当前唯一 active advanced group；
  - 不是差一张即可合成/升级的 stack；
  - 不是未完成的祝福、成长、经济、挑战、智/敏/力；
  - 不是带计时/残骸/符文/吞噬进度的承重卡；
  - 不会破坏当前已经启动的卡池解锁链；
- 吞后要看到 fresh frame 的目标消失 + occupancy 下降；仅“丹图标没了”不算成功。

如果普通丹的目标机制最终被实测证明为不可选/随机，则 [inferred] 只有“所有可能被吞的当前可吞卡都安全”时才应自动吃；否则继续零输入。

## “贪婪”该排哪一档？

建议：条件工具档，不进入 Owner 的无条件基础卡主序列。[inferred]

Owner 当前无条件基础序列是：

> 祝福 → 成长 → 经济 → 挑战 → 智力/敏捷/力量 → 其他基础卡

贪婪虽然依赖经济，收益看起来很高，但它的核心动作是随机吞 4 张可吞卡 [live]。这会带来比普通基础卡大得多的状态依赖：

- [guide] 5分钟亡灵攻略故意先把“亡灵 4 个房子”准备好，最后一手才让贪婪清场；
- [guide] 另一些物理攻略直接写某些阶段“贪婪有都别点”，避免破坏卡池；
- [guide] 海盗/三国路线又会利用贪婪吞海盗省悬赏令。

因此 [inferred] 最合理的自动化语义不是“经济之后固定拿贪婪”，而是：

> 经济解锁后，把贪婪登记成高收益但高破坏性的 side-tool；只有当前随机吞 4 张的候选集合全部可接受，或当前 active chain 明确需要这次吞噬时，才临时升到高优先。
